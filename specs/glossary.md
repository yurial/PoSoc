## 13. GLOSSARY

**Records**

- **Consent object** — TTL-запись с автопродлением и мгновенным revoke; четыре типа: `LINK`, `SELF_CONF`, `VOUCH`, `DECLARE` (§2.3).
- **Action** — запись с мгновенным эффектом, без TTL (§2.3).
- **`X_REVOKE`** — паттерн именования: action, отзывающий consent object типа X; подписант revoke совпадает с подписантом объекта (§2.3).
- **`LINK`** — consent object пары ключей; обе подписи (§3.1).
- **`LINK_REVOKE`** — односторонний разрыв: terminирует instance, создаёт poison mark против контрагента (§3.2).
- **`SELF_CONF` / `SELF_CONF_REVOKE`** — само-подтверждение членства в L0 / его отзыв (выход) (§4.2).
- **`VOUCH` / `VOUCH_BATCH` / `VOUCH_REVOKE`** — поручительство члена за кандидата / пакет / отзыв; quorum отзывов = исключение (§4.2).
- **`DECLARE` / `DECLARE_REVOKE`** — голос в C1-quorum / мгновенный отзыв (лёгкое возражение) (§5.2).
- **`L0_GENESIS`** — адрес L0; без привилегий (§4.5).

**Time & state**

- **$t_{sign}$** — подписанное автором время записи; единственный источник времени (§2.4.1).
- **$now()$** — субъективные часы узла (§2.4.1).
- **Future rule / $\Delta$** — $t_{sign} > now+\Delta$: discard с пере-оценкой; в коридоре: deferred (§2.4.2).
- **LWW** — для записей одного назначения действует max $t_{sign}$; замещение при строго большем; равные → меньший $H(\mathrm{record})$ (§2.4.4).
- **Designation** — identity записи для конфликтов: тип + ключевые поля (для парных — включая направление) (§2.4.4).
- **Reconstruction** — нормативное вычисление: сортировка по $(t_{sign}, H(\mathrm{record}))$, последовательное применение (§2.4.6).
- **Stored record set** — хранимое множество записей; аргумент функции состояния (§2.4.8).
- **Re-publish** — повторная публикация живых declarations при изменении membership-статуса (§2.4.9).

**Links**

- **Instance** — текущий `LINK` пары; замещается более свежим (§3.1).
- **Binding** — привязка `LINK_REVOKE` к последнему instance с $t_c \le t_{sign}$ (§3.2.2).
- **Winning revoke** — действующий revoke направления: max $t_{sign}$ на instance (§3.2.3).
- **Mutual revoke** — revoke обоих направлений одной пары; не конфликтуют; обе стороны помечены (§3.2.3).
- **Counter-revoke** — свежая запись того же направления; замещает и отменяет mark подделки в любой момент (§3.2.5).
- **Poison mark** — активна на $[t_b, \min(t_c+T_{life}, t_{relink}))$; ≤1 на пару-направление, ≤2 на пару (§3.2.4).
- **Clamp** — $t_b = \min(t_{sign},\ t_c + T_{life})$: разрыв зажат в базовое окно instance (§3.2.4).
- **$N_x$** — число активных marks против $x$; $N_x \le \deg(x)$ (§3.2).
- **Window / decay** — $W = T_{life}/(1+N_u+N_v)$; $d(\ell)$ — момент распада; необратимость — относительно текущего множества записей (§3.3).
- **Truce** — свежий `LINK` пары: усекает marks обоих направлений, расширяет окна выживающих связей (§3.2, св. 3).
- **GC horizon** — записи пары хранятся до $t_{last}+2T_{life}$; дальше — не влияют ни на что (§2.2.5, §3.4.1).

**L0**

- **Candidate** — ключ с живой `SELF_CONF` (§4.3.1).
- **Materialization** — вхождение кандидата в активный roster (§4.4).
- **Active member** — участник, прошедший rounds (§4.3).
- **Vouch-quorum** — $\lfloor |M|/2 \rfloor + 1$ живых `VOUCH` (§4.3.4a).
- **Cohesion** — $\lfloor |M|/2 \rfloor + 1$ активных связей с активными членами (§4.3.4b).
- **Synchronous rounds** — одновременное удаление нарушителей до фикс-точки; sound, не maximal (§4.3.4).
- **Growth priority** — начальный roster = все кандидаты; присоединение никогда не блокируется (§4.3.3).
- **Squeeze-out** — вытеснение incumbents укрупнёнными порогами; принятая семантика (§4.3.3, §10.16).
- **Cap-30** — отбор кандидатов: vouch count → $t_{sign}$ → pk (§4.3.2).
- **Freshness tie-break** — равные притязания → fresher $t_{sign}$ (§4.3.5).
- **Quench** — $|M_{act}| < 4$: roster пуст, edges отваливаются каскадом (§4.3.6).

**Hierarchy**

- **Isolate** — 0 живых детей; $R_{str} = \varnothing$; привязывается только bootstrap (§5.5, §5.6.2).
- **Vertex** — ≥ 2 живых детей (§5.5).
- **Free group** — 1 живой ребёнок; edge грандфатерится; общие правила (§5.5, §5.6.2).
- **Edge / child / parent / sister** — привязка $X \to H$; X — child, H — parent; другие дети H — sisters (§5.5).
- **C1** — quorum живых declarations (§5.5).
- **C2 (all-pairs)** — corroboration: пары со всеми живыми сёстрами (§5.5).
- **C3** — acyclicity (§5.5).
- **Hold window ($T_{hold}$)** — непрерывное выполнение условий перед активацией (§5.5).
- **Freeze ($T_f$)** — блокировка новых активаций вверх после `L0_GENESIS` и bootstrap; параллелен hold window (§5.5).
- **Bootstrap / S-set** — совместная активация ≥ 2 рёбер к пустой группе; все пары внутри $S$; окно на фиксированном $S$; выбор: inclusion-maximal → ранний старт → лексикографический минимум (§5.5).
- **Attach / detach** — присоединение к живой группе / мгновенный отрыв (провал C1 или любой пары — оба edge) (§5.5–5.6).
- **Demotion** — vertex → free group (1 ребёнок) → isolate (0) с отвалом восходящих edges тем же пересчётом (§5.6.2).
- **Grandfathered edge** — edge свободной группы, сохранённый при понижении (§5.6.2).
- **$R_{str}$ / $R_{decl}$** — структурный roster (союз живых детей; задаёт численности) / roster заявлений (не носитель доверия) (§5.3).
- **Level ($L$)** — $1 + \max$ по живым детям; метаданные (§5.6.3).
- **Multi-parenting** — группа — ребёнок любого числа родителей; штатное состояние DAG (§5.6.4).
- **Disjoint count ($U$)** — corroboration только во внешнюю часть контрагента (§5.4.1).
- **$f$-curve / $\gamma$ / $\kappa$ (conspiracy floor)** — пороговая арифметика пар (§5.4.2).

**Network**

- **Neighbor** — узел с активной LINK; транспорт совпадает с графом доверения (§2.2.1).
- **Sync queue** — исходящий буфер ретрансляции (§2.2).
- **Anti-entropy** — периодическая сверка множеств записей; подавляет цензуру и потери (§2.2.3).
- **Mandatory zone** — свои связи и группы; глубже — политика узла (§2.2.4).
- **Relevance** — политика хранения/ретрансляции, не валидности (§2.6.1).
- **Caps / rate-limit** — детерминированные лимиты живых объектов и обновлений на ключ (§2.6).

**Trust**

- **Proof (subtree)** — все дети каждого parent на пути + перекрёстные связи (C2) + численности (§6.1).
- **Spot-check** — опрос $k$ случайных участников rosters о записях, затрагивающих proof; расхождение → reject; SHOULD (§6.3).
- **Trusted set** — транзитивное замыкание родителей L0 верификатора + его политика (§6.2).
- **Inclusion cost** — $\approx t$ взаимных живых связей, рекуррентно $\le T_{life}$ (§1.3).
- **Hijack localization** — сжатие окон в $1+N$; чужие marks нестерираемы; counter-revoke против бэйдейтинга (§7.3).
