## 6. Потребление доверия

<a id="trust-6"></a>

### 6.1 Proof membership

<a id="trust-6.1"></a>

Доказательство — **поддерево**, не путь: для каждого parent на пути предъявляются все живые дети, их перекрёстные связи (C2), численности $R_{str}$, живые declarations (C1), плюс собственная L0 заявителя (SELF_CONF + vouches + связи). Причина: валидность одного edge — свойство всего множества детей. Сильный режим — верификация по собственной replica (чистая функция состояния). Декларации в доверии не участвуют. Commit-structures (Merkle-корни поддеревьев) для лёгких верификаторов — roadmap ([ZKP-11](11_privacy_zkp.md#zkp-11)).

### 6.2 Субъективная оценка

<a id="trust-6.2"></a>

Доверенное множество — транзитивное замыкание родителей L0 верификатора (+ его политика: размер, возраст, аномалии [DEF-7.4](07_defenses.md#def-7.4)). Глобального флага «человек» нет. Практическая картина: люди — гигантский компонент; бот-кластеры — изолированные компоненты (структурно и транспортно).

### 6.3 Spot-check (SHOULD; расшифровка)

<a id="trust-6.3"></a>

<a id="trust-6.3-a"></a>

**Проблема.** Prover может утаить неблагоприятные записи (`SELF_CONF_REVOKE`, `VOUCH_REVOKE`, `LINK_REVOKE`, распад связей). Верификатор без полной копии не видит неполноту предъявленного множества — это главный вектор обмана лёгкого верификатора.

<a id="trust-6.3-b"></a>

**Механизм.** Верификатор выбирает $k$ случайных участников из предъявленных rosters и запрашивает у них (транспорт — social graph верификатора / anti-entropy pull к собственной replica) записи, затрагивающие proof: живость SELF_CONF/VOUCH/DECLARE и активность связей поддерева. Расхождение с предъявленным → reject.

<a id="trust-6.3-c"></a>

**Свойства.** Записи публичны в компоненте: утаивание prover'ом не мешает другим узлам ими владеть; обнаружение утаивания — с вероятностью $\approx 1-(1-p)^k$, где $p$ — доля опрошенных, владеющих противоречащей записью. Запросы liveness — вне гарантий.

<a id="trust-6.3-d"></a>

**Пределы.** Скоординированное сокрытие целым компонентом; верификатор без независимых путей к данным. Сильный режим (собственная replica) от этих пределов свободен.

<a id="trust-6.3-e"></a>

**Статус:** SHOULD — политика клиента; на консенсус не влияет.
