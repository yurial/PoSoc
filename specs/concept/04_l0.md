## 4. Базовые группы (L0)

<a id="l0-4"></a>

### 4.1 Принцип

<a id="l0-4.1"></a>

L0 — реальные малые группы. Membership — **непрерывный двусторонний предикат**: само-членство ∧ подтверждения группы ∧ link-опора. Ни ростер, ни запись не включают $P$ без подписи $P$; пребывание — при поддержке большинства. Вход двусторонен; revoke и выход — односторонни.

### 4.2 Объекты

<a id="l0-4.2"></a>

- <a id="l0-4.2.1"></a>**`MEMBER_OF(X,G)`** — «X member of G» (TTL, продлевается клиентом подписанта): подписант = $X$ — само-членство; подписант ≠ $X$ — подтверждение членства другого. Тип членства един для всех групп; различение сценариев — по типу ID группы: $ID_G$ — базовая группа L0, $ID_H$ — сообщество иерархии, где живые `MEMBER_OF(P,H)` образуют $R_{decl}(H)$ и голосуют в C1-quorum ([HIER-5.2](05_hierarchy.md#hier-5.2)).
- <a id="l0-4.2.3"></a>**`MEMBER_OF_REVOKE(X,G)`** с подписантом $X$ — выход: membership $X$ прекращается немедленно, односторонне.
- <a id="l0-4.2.4"></a>**`MEMBER_OF_REVOKE(X,G)`** с подписантом-подтверждающим — отзыв своего подтверждения; **quorum отзывов** роняет поддержку немедленно — это и есть исключение (события EXPEL не существует).

### 4.3 Roster computation (growth priority)

<a id="l0-4.3"></a>

Membership = **выход детерминированного алгоритма** на $\tau$:

1. <a id="l0-4.3.1"></a>**Candidates:** все $P$ с живым само-членством `MEMBER_OF(P,G)` (подписант = $P$).
2. <a id="l0-4.3.2"></a>**Cap-30 (до раундов):** при $>30$ кандидатов берутся 30: (i) по числу живых `MEMBER_OF(·,G)` от других кандидатов — подписант ≠ кандидат, счёт по уникальным подписантам (убыв.); (ii) при равенстве — fresher $t_{sign}$ само-членства `MEMBER_OF`; (iii) при равенстве — $pk$ (возр.). Непопавшие остаются кандидатами (записи не теряются, re-publish не нужен).
3. <a id="l0-4.3.3"></a>**Growth priority:** начальный roster = **все** отобранные кандидаты. Присоединение никогда не блокируется маргинальностью incumbents: если укрупнённые пороги инвалидируют incumbents — они удаляются раундами (**squeeze-out** — принятая семантика, [LIM-10.16](10_limitations.md#lim-10.16)).
4. <a id="l0-4.3.4"></a>**Synchronous rounds:** на каждом раунде **одновременно** удаляются все, нарушающие относительно текущего roster:
   <a id="l0-4.3.4-a"></a>(a) **кворум подтверждений:** живых `MEMBER_OF(·,G)` от текущих членов (подписант ≠ кандидат; само-членство в кворум не входит) ≥ $\lfloor |M|/2 \rfloor + 1$;
   <a id="l0-4.3.4-b"></a>(b) **cohesion:** активных связей с текущими членами ≥ $\lfloor |M|/2 \rfloor + 1$.
   Итерация до стабилизации. Результат **sound** (инварианты выполнены); **maximality не гарантируется** и не заявляется. Вычисление детерминировано.
5. <a id="l0-4.3.5"></a>**Freshness tie-break:** любые равные притязания в L0-вычислениях (cap, равные счёты) → fresher $t_{sign}$, затем $pk$.
6. <a id="l0-4.3.6"></a>**Quench:** $|M_{act}| < 4$ → roster пуст; edges от группы отваливаются мгновенным каскадом ([HIER-5.6](05_hierarchy.md#hier-5.6)).

### 4.4 Динамика: две скорости

<a id="l0-4.4"></a>

- <a id="l0-4.4.1"></a>**Явные действия — мгновенны:** `MEMBER_OF_REVOKE` от себя (выход), quorum `MEMBER_OF_REVOKE` от подтверждающих (исключение), потеря cohesion (удаление раундом при следующем пересчёте).
- <a id="l0-4.4.2"></a>**Угасание — ≤ $T_{life}$:** expire без продления покрывает мёртвые узлы.
- <a id="l0-4.4.3"></a>**Вступление/возвращение:** материализация = живое само-членство `MEMBER_OF` + подтверждения других членов; после угасания поддержки — только заново набранный quorum. В норме продление тихое.
- <a id="l0-4.4.4"></a>Roster мгновенно входит в $R_{str}$ → пороги → edges ([HIER-5.6](05_hierarchy.md#hier-5.6)).

### 4.5 Genesis

<a id="l0-4.5"></a>

`L0_GENESIS(initiator, descriptor, t_sign)` задаёт адрес $ID_G$ ([FMT-2.8](../implementation/01_records_formats.md#fmt-2.8)) — без привилегий. Группа жива, когда ≥ 4 участников удовлетворяют [L0-4.3](#l0-4.3) (их само-членства и взаимные подтверждения `MEMBER_OF` — обычные объекты). Церемоний нет: genesis — адрес, остальное — непрерывный предикат.
