## 1. Назначение, принципы, модель угроз

<a id="prin-1"></a>

### 1.1 Назначение

<a id="prin-1.1"></a>

Цель — децентрализованная сеть доверия (**PoSoc — Proof of Social**), позволяющая каждому участнику отличать реальных людей от ботов/виртуальных аккаунтов **в пределах наблюдаемого им компонента социального графа**. Гарантии — условные и вероятностные, в терминах стоимости атаки.

### 1.2 Принципы

<a id="prin-1.2"></a>

<a id="prin-1.2.1"></a>

1. **Отсутствие инфраструктуры.** Нет корневых узлов, валидаторов, ledger, субстрата упорядочивания. Сеть — участники и их связи.

<a id="prin-1.2.2"></a>

2. **Одноранговость.** Полномочий нет; каждый валидирует состояние сам.

<a id="prin-1.2.3"></a>

3. **Субъективное локальное доверие.** Участник доверяет иерархиям, достижимым из его L0 ([TRUST-6](06_trust.md#trust-6)).

<a id="prin-1.2.4"></a>

4. **Стоимость вместо альтруизма.** Протокол не предполагает честности: подтверждение ботов — стоимостно и рекуррентно. Подкуп и обман — векторы стоимости ([PRIN-1.3](#prin-1.3)).

<a id="prin-1.2.5"></a>

5. **Публичность внутри компонента.** Записи публичны в компоненте связности; валидность — чистая функция данных.

<a id="prin-1.2.6"></a>

6. **Эфемерность.** Все факты — автопродлеваемые TTL-объекты с мгновенным revoke; «купленного» факта не существует.

<a id="prin-1.2.7"></a>

7. **Взаимность согласия.** Вход двусторонен (обе подписи / quorum); revoke и выход — односторонни. Молчаливого согласия нет.

<a id="prin-1.2.8"></a>

8. **Эмерджентность иерархии.** Edges и levels — выводимое состояние, не записи.

<a id="prin-1.2.9"></a>

9. **Время подписи.** Состояние — функция множества подписанных записей и текущего времени; порядок доставки семантики не имеет.

<a id="prin-1.2.10"></a>

10. **Единая семантика revoke.** Каждый consent object X отзывается действием `X_REVOKE` того же подписанта; свежая подпись всегда сильнее старой.

### 1.3 Модель угроз

<a id="prin-1.3"></a>

<a id="prin-1.3.1"></a>

**Противник может:** создавать неограниченно ключей (Sybil); контролировать связи своих узлов; создавать группы и declarations (permissionless); получать связи с людьми (встреча, обман, подкуп); похищать ключи; бэйдейтить $t_{sign}$ собственных записей; задерживать/утаивать записи при ретрансляции; смещать собственные часы.

<a id="prin-1.3.2"></a>

**Противник не может (криптографически):** подделать подпись; создать/продлить consent object без требуемых подписей; включить участника в L0 без его подписи; отозвать чужой consent object; аннулировать poison mark без подписи создавшей стороны или fresh LINK пары; привязать группу к иерархии без живых внешних связей и quorum declarations.

<a id="prin-1.3.3"></a>

**Гарантии (в пределах допущений):**

<a id="prin-1.3.3-a"></a>

- *Inclusion cost:* включение бот-компонента в человеческую иерархию требует $\approx t$ взаимных живых связей; линейно по порогу, рекуррентно ($\le T_{life}$).

<a id="prin-1.3.3-b"></a>

- *Isolation:* declarations без внешних живых связей не создают edges (disjoint count, [HIER-5.4](05_hierarchy.md#hier-5.4)); транспортная изоляция дублирует структурную ([ARCH-2.2](02_architecture.md#arch-2.2)).

<a id="prin-1.3.3-c"></a>

- *Backdating containment:* поддельный revoke живёт до момента counter-revoke; свежая подпись жертвы всегда сильнее ([LINK-3.2](03_links.md#link-3.2)).

<a id="prin-1.3.3-d"></a>

- *Hijack localization:* окна сжимаются в $1+N$ раз; чужие marks угонщик не стирает; исключение — quorum отзывов, мгновенно.

<a id="prin-1.3.4"></a>

**Негарантии:** многоличность ([LIM-10.2](10_limitations.md#lim-10.2)); сговор выше порогов ([LIM-10.5](10_limitations.md#lim-10.5)); приватность ([ZKP-11](11_privacy_zkp.md#zkp-11)); мгновенная глобальная согласованность ([ARCH-2.5](02_architecture.md#arch-2.5)); гарантированная доставка ([LIM-10.9](10_limitations.md#lim-10.9)–[LIM-10.10](10_limitations.md#lim-10.10)).
