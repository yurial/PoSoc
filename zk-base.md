# Спецификация протокола PoSoc (v0.8)

## 1. Назначение, принципы, модель угроз

### 1.1 Назначение

Цель — децентрализованная сеть доверия (**PoSoc — Proof of Social**), отличающая реальных людей от ботов/виртуальных аккаунтов и разделяющая их на непересекающиеся множества: компоненты реальных людей и изолированные компоненты ботов.

Гарантии протокола — **условные и вероятностные**: они опираются на допущения §1.2–1.3 и формулируются в терминах стоимости атаки, а не как абсолютные свойства.

### 1.2 Базовые принципы

1. **Отсутствие корневых узлов.** Нет верифицированных, привилегированных или Genesis-участников. Нейтральная инфраструктура упорядочивания событий (§2.2) не является «узлом» и не принимает решений о валидности групп.
2. **Одноранговость.** Нет валидаторов и иных ролей с полномочиями; каждый участник полностью валидирует своё состояние сам (§2.2).
3. **Субъективное локальное доверие.** Участник доверяет группам, входящим в иерархии его базовых L0-групп (§6). Изолированные компоненты графа им не доверяются.
4. **Социальная ответственность.** Предполагается, что участники не подтверждают ботов ради искусственного объединения групп. Проблема подкупа **намеренно выведена из модели угроз** (§1.3).
5. **Публичная криптография.** Все связи, ростеры, декларации и операции публичны; валидность — чистая функция публичных данных; публичность открывает **поиск аномалий** (§7.4). Приватизация через ZKP — направление развития (§11).
6. **Эфемерность структуры.** Ни связь, ни членство, ни привязка группы не являются однажды «купленным» фактом: всё требует поддержки и перепроверяется на текущем состоянии.
7. **Взаимность согласия.** Каждый акт доверия двусторонен: связь — две подписи; членство в L0 — само-аттестация участника плюс принятие группой; привязка группы — кворум деклараций присоединяющейся группы плюс корроборация связями. Односторонних утверждений о доверии не существует; односторонни только разрыв, выход и отзыв. Молчаливого согласия не существует — согласие всегда позитивно и всегда отзываемо.
8. **Эмерджентность иерархии.** Участники не строят иерархию явно. Явные акты пользователя — установление связей, членство в L0 и **декларирование принадлежности к группам**. Рёбра иерархии, уровни и валидность — **выводимое состояние**: функция деклараций, активных связей и численностей, детерминированно перевычисляемая каждую эпоху. Церемоний слияний не существует.

### 1.3 Модель угроз и границы гарантий

**Противник может:** создавать неограниченное число ключей (Sybil); полностью контролировать связи между своими узлами; создавать любые группы и массово декларировать любые принадлежности (декларации permissionless); получать связи с людьми (встреча, обман, подкуп); похищать закрытые ключи.

**Противник не может (криптографически):** подделать подпись; создать или обновить связь без встречной подписи контрагента; включить участника в L0 без его собственной подписи; разорвать чужую связь; аннулировать метку яда без подписи разорвавшей стороны (§3.2); **привязать группу к иерархии без живых внешних связей и кворума деклараций** (§5).

**Гарантии (при допущениях §1.2):**
- *Стоимость включения.* Включение ботов в человеческую иерархию требует $\approx t(A,B)$ взаимных связей с реальными людьми; стоимость линейна по порогу и **рекуррентна**.
- *Изоляция.* Декларации ничего не стоят и ничего не дают: без внешних живых связей компонент не привязывается (§5.4 — дизъюнктный подсчёт исключает корроборацию co-membership).
- *Локализация угона.* Угнанный аккаунт отторгается тем быстрее, чем больше разрывов против него: окно связей сжимается в $1+N$ раз (§7.3); изоляция устойчива к отмыванию.

**Негарантии (осознанные ограничения):** многоличность (§10.2); сговор выше порогов (§10.5); приватность графа и деклараций (§11).

## 2. Архитектура

### 2.1 Идентичность

1. Личность — пара ключей $(x,\ pk)$, Ed25519 (§8). Секрет $x$ никогда не публикуется.
2. Отдельной «регистрации» нет: ключ существует, если фигурирует хотя бы в одном валидном событии. Sybil-устойчивость обеспечивает не реестр, а социальный граф.
3. Один человек может владеть несколькими ключами (§10.2).

### 2.2 Одноранговая сеть и публичный журнал

**Валидаторов нет.** Протокол не определяет ролей с полномочиями. Сеть одноранговая.

1. **Распространение.** События распространяются gossip-протоколом между равными узлами.
2. **Полная локальная валидация.** Каждый участник проверяет подписи и каноническую форму всех событий, детерминированно вычисляет производное состояние (§2.3) и перепроверяет валидность групп и привязок. Валидации «чужими руками» не существует.
3. **Некорректные события.** Журнал может содержать мусор — субстрат упорядочивания не проверяет правила PoSoc. Каждый узел **детерминированно игнорирует**: события с неверными подписями, неканонической формой, дубликаты по содержимому и события с неприменимым переходом (например, `BREAK` без активной связи, `L0-JOIN` со старой версией состава, `G-LEAVE` без действующей декларации). Правила игнорирования — часть спецификации: результат вычисления состояния одинаков у всех узлов.
4. **Базовая модель узла — полная реплика журнала.** Масштабирование — верифицируемые чекпойнты (снапшот + хеш-цепочка к генезису), проверяемые локально.
5. **Субстрат упорядочивания.** Журнал требует тотального порядка и финальности; допустим любой механизм — он не интерпретирует правила PoSoc и не влияет на валидность групп. Требования: append-only, детерминированный тотальный порядок, финальность, доступность данных, разумная устойчивость к цензуре; антиспам-политика — за субстратом.

*Пояснение.* Консенсус отвечает на вопрос «в каком порядке произошли события», PoSoc — «что из этого следует». Все выводы каждый участник делает сам.

### 2.3 События и производное состояние

| Событие | Подписи | Назначение |
|---|---|---|
| `LINK(u, v)` | обе стороны | новый экземпляр связи пары; замещает прежний и **перетирает разрывы пары** (§3) |
| `BREAK(u → v)` | $u$ | разрыв текущего экземпляра; метка яда против $v$ (§3.2) |
| `G-DECLARE(P, H)` | $P$ | заявить/продлить принадлежность $P$ к группе $H$ (§5.2) |
| `G-LEAVE(P, H)` | $P$ | отозвать принадлежность (§5.2) |
| `L0-GENESIS(ID, roster)` | каждый член (само-аттестации) | создание L0 (§4) |
| `L0-ATT(G, P, epoch)` | $P$ | само-аттестация членства в L0 (§4) |
| `L0-JOIN(G, ver, P)` | $P$ + вуши кворума | приём члена (§4) |
| `L0-LEAVE(G, ver, P)` | $P$ | выход члена (§4) |
| `L0-EXPEL(G, ver, P)` | кворум кроме $P$ | исключение члена (§4) |

Событий слияний, вето, предложений и якорей **не существует**: рёбра иерархии — производное состояние (§5).

**Производное состояние** (чистая функция журнала): текущие экземпляры связей, метки яда и $N_x$, моменты распада; составы L0; декларации и группы (ростеры-заявления, дети, уровни, фризы); статусы рёбер (гистерезис). Неактивное (распавшиеся связи, пассивные члены, погасшие декларации, отпавшие рёбра) исключается из активного состояния, но сохраняется в архиве (анализ §7.4).

### 2.4 Канонизация

- Детерминированная сериализация (канонический CBOR: ключи отсортированы); пары ключей упорядочиваются лексикографически; самосвязи запрещены.
- $\mathrm{sort}(\cdot)$ — лексикографический порядок байтовых строк; $pk$ — raw-байты.
- $H$ — BLAKE3 с доменным разделением по типам объектов (§8).
- Округления в порогах (§5.4) — с допуском $\lfloor x + \varepsilon \rfloor$, $\varepsilon = 10^{-9}$.

## 3. Связи

### 3.1 Экземпляры связей: установление, обновление, перемирие

1. Связь — отношение между парой ключей $(u, v)$. В каждый момент у пары существует **не более одного актуального экземпляра**.
2. `LINK(u, v)` (подписи обеих сторон) создаёт **новый экземпляр** с моментом $t_c$. Установление и обновление — единая операция: свежий экземпляр **замещает** прежний (архив); окно жизни (§3.3) отсчитывается заново.
3. **Перетирание разрывов.** `LINK(u, v)` аннулирует активные метки яда, созданные `BREAK(u → v)` и `BREAK(v → u)`: интервалы активности меток усекаются моментом события. Новый экземпляр пары чист от её **собственных** разрывов; его окно сужается только метками третьих лиц.
4. **Машина состояний пары.** Живая / разорванная / распавшаяся / нейтральная. Переходы: `LINK` → живая (из любого состояния, из разорванной — с перетиранием); `BREAK` → разорванная (только из живой); истечение окна → распавшаяся; истечение метки → нейтральная. Оживление распавшейся пары — только её собственным `LINK`.

### 3.2 Разрыв и яд (Poison)

**Разрыв.** `BREAK(u → v, memo)` — одностороннее событие $u$, применимое только к **живому** экземпляру (иначе детерминированно игнорируется):

1. Немедленно уничтожает текущий экземпляр; `memo` — необязательный публичный комментарий.
2. Создаёт **метку яда**:
$$\mu = (\text{пара}: (u,v),\ \text{против}: v,\ t_b,\ t_{end}),\qquad t_{end} = \min\big(t_c(\ell) + T_{1/2},\ t_{\mathrm{relink}}\big)$$
где $\ell$ — разорванный экземпляр, $t_{\mathrm{relink}}$ — момент ближайшего последующего `LINK(u,v)` (нет — $\infty$). Метка активна на $[t_b,\ t_{end})$.
3. Журнал неизменяем: перетирание — семантика производного состояния; история разрывов остаётся в архиве (§7.4).

**Яд.** Окно жизни экземпляра $\ell = (a,b)$:
$$W_\ell(t) = \frac{T_{1/2}}{1 + N_a(t) + N_b(t)},$$
где $N_a(t)$ — число активных меток против $a$.

**Свойства:**

1. **Направленность.** Травится покинутый.
2. **Стекирование и инвариант пары.** Метки **разных** пар суммируются; **одной** пары не перекрываются (разрыв требует живого экземпляра, `LINK` пары обнуляет её метку): не более одной активной метки на пару. Следствие: $N_a \le \deg(a)$.
3. **Перемирие лечит.** `LINK(u,v)` мгновенно аннулирует метки этой пары; окна **выживающих** связей $u$ и $v$ расширяются немедленно. Метки третьих лиц не затрагиваются: чужое недоверие прощается только временем.
4. **Восстановление — два пути:** истечение ($\le T_{1/2}$ после разрыва) либо перемирие (мгновенно, подписи обеих сторон). Распавшиеся связи не оживают ничьим перемирием — только собственным `LINK`.
5. **Отмывание недоступно.** Аннулирование метки требует `LINK` пары — подписей обеих сторон, **включая разорвавшую**. Держатель угнанного ключа не может стереть метки, созданные друзьями жертвы.
6. **Цена грифинга.** Цикл `LINK→BREAK→LINK→…` требует подписи «жертвы» на каждый `LINK`; собственные метки пары не накапливаются.
7. **Каскад разрывов** против одного ключа — сильный публичный сигнал компрометации (§7.4).

*Пример* ($T_{1/2}=12$ мес.). Разрыв $(a,b)$ в $t{=}2$ (экземпляр с $t_c{=}0$): метка на $[2,12)$. Связь $(b,c)$ ($t_c{=}0$) получает окно 6 мес. и распалась бы в $t{=}6$; перемирие `LINK(a,b)` в $t{=}4$ аннулирует метку: окно $(b,c)$ немедленно расширяется до 12, распад отодвигается на $t{=}12$ — выживающая связь спасена; сама пара $(a,b)$ — свежий экземпляр до $t{=}16$.

### 3.3 Распад (Trust Decay)

**Все связи имеют время жизни.** Экземпляр $\ell$, созданный в $t_c$, распадается в
$$d(\ell) = \min\{\tau \ge t_c:\ \tau - t_c \ge W_\ell(\tau)\}$$
(распад не позднее $t_c + T_{1/2}$).

1. **Активная связь** — экземпляр не разорван, не замещён, не распался. Только активные связи участвуют во всех подсчётах.
2. **Необратимость.** Распад — жёсткое отсечение; расширение окна (истечение/аннулирование меток) отодвигает распад выжившего, но не оживляет распавшийся.
3. **Вычислимость.** $W$ кусочно-постоянна; $d(\ell)$ вычисляется сканированием моментов разрывов/истечений/перемирий.
4. Распад каскадно влечёт перепроверку членств и привязок (§5.8).

*Примеры* ($T_{1/2}=12$ мес.): 1 разрыв → 6 мес.; 3 → 3 мес.; 7 → ≈1.5 мес.

### 3.4 Межгрупповые связи

Для групп $X, Y$ и множества активных связей определяется **дизъюнктный подсчёт** $U_{X \Rightarrow Y}$ (§5.4) — участники $X$ с активными связями во **внешнюю** часть $Y$.

## 4. Базовые группы (L0)

### 4.1 Членство: взаимный акт

1. Листовые группы — **L0**; соответствуют реальным малым группам (соседи, одноклассники, коллеги). Реальность подтверждается личными встречами.
2. **Членство участника $P$ в L0 — двусторонний акт:** $P$ подписывает **само-аттестацию**; группа подписывает **принятие** (вуши членов).
3. **Самоподпись членства обязательна и незаменима.** Ни один ростер или изменение состава не могут включить $P$ без подписи $P$. Это исключает включение против воли, фабрикацию составов и «заложное» членство.
4. Асимметрия намеренна: **вход требует согласия самого участника, пребывание — большинства группы**.

### 4.2 События жизненного цикла

Состав — производное состояние: свёртка событий в порядке журнала; события ссылаются на **версию** состава и применяются только к текущей голове. $ID_G$ фиксируется на генезисе.

1. **Генезис** `L0-GENESIS(ID, roster)`: $4 \le n \le 30$; каждый член публикует само-аттестацию. $ID_G = H(\mathrm{sort}\{pk_i\}\ \Vert\ \texttt{epoch}_{genesis})$.
2. **Приём** `L0-JOIN(G, ver, P)`: само-аттестация $P$ + вуши $\ge \lfloor |M|/2 \rfloor + 1$ текущих активных членов; итог $\le 30$.
3. **Выход** `L0-LEAVE(G, ver, P)`: подпись $P$.
4. **Исключение** `L0-EXPEL(G, ver, P)`: подписи $\ge \lfloor (|M|-1)/2 \rfloor + 1$ членов кроме $P$; подпись исключаемого **не требуется** (иначе угнанный ключ нельзя удалить). Возврат — через `JOIN`.
5. **Само-аттестация** `L0-ATT(G, P, epoch)`: окно $T_m$ (2 эпохи); явное действие пользователя, не чаще раза в эпоху.
6. Вуши действительны бессрочно (факт приёма); действительность членства определяется свежестью аттестации и событиями выхода/исключения.

### 4.3 Состояния членства

1. **Активный** — свежая аттестация, не выходил, не исключён; входит в ростер для всех подсчётов.
2. **Пассивный** — аттестация просрочена (молчаливый выход); новая аттестация восстанавливает членство без повторных вушей.
3. **Покинувший/исключённый** — возврат только через `JOIN`.

### 4.4 Валидность

1. $4 \le |M_{active}| \le 30$;
2. **когезия:** каждый активный член имеет активные связи не менее чем с $N = \lfloor |M_{active}|/2 \rfloor + 1$ другими активными членами.

Валидность вычисляется каждым узлом. Верхняя граница принудительна на уровне событий; нижняя — свойство активного ростера.

### 4.5 Ремонт и распад

Нарушение → статус «ремонт» на одну эпоху (связи, аттестации, `EXPEL`, **перемирие** — §3.2). Безуспешно → распад: компоненты, удовлетворяющие §4.4, пере-генезируются как новые L0; участие в привязках — по общим правилам §5.

## 5. Эмерджентная иерархия: декларации и выводимые привязки

### 5.1 Принцип

Участники не строят иерархию явно. Единственные явные акты — связи, членство в L0 и декларации. Рёбра «ребёнок → родитель», уровни и валидность — **выводимое состояние**: детерминированная функция журнала (декларации + активные связи + численности), перевычисляемая каждую эпоху. Никто не «запускает проверку» и не «утверждает» ребро; условия меняются со временем, привязка — непрерывно перевычисляемый предикат с гистерезисом (§5.7).

### 5.2 Декларации и группы

1. **Декларация** `G-DECLARE(P, H)` — подписанное $P$ заявление о принадлежности к группе $H$; действует окно $T_m$ (2 эпохи), продлевается повторной декларацией. **Отзыв** `G-LEAVE(P, H)` — немедленен. Декларации permissionless: никто не может запретить заявить принадлежность.
2. **Идентификация группы.** $ID_H = H(\texttt{"GROUP"} \,\Vert\, \texttt{descriptor} \,\Vert\, pk_{genesis})$; группа создаётся первой декларацией ($pk_{genesis}$ — техническая роль адресации, без привилегий). Дескриптор — публичная метка; имя — не идентичность (§10.1).
3. **Изолят** — группа без привязок и без уровня. Живёт, пока есть свежие декларации; без них гаснет (архив). Изолят может бутстрапнуться (§5.6) в любой момент.
4. Декларации **посторонних** (не входящих в структурный ростер какой-либо группы-кандидата) ни на что не влияют — кворумы (§5.5) считаются только по членам структурных ростеров.

### 5.3 Ростеры и членство

1. **Ростер-заявления** $R_{decl}(H)$ — участники со свежими декларациями в $H$. Выражает согласие и идентичность сообщества; **не является носителем доверия и не участвует в порогах**.
2. **Структурный ростер** $R_{str}(H) = \bigcup_{C \in \mathrm{children}(H)} R_{str}(C)$ — по уникальным pk живых детей; для L0 — активный ростер §4. Только он определяет **численность $|H|$ для всех порогов** и принадлежность к иерархии.
3. Участник «находится в иерархии» ⟺ состоит в валидной L0, транзитивно привязанной к доверенному компоненту. Декларация сама по себе этого не даёт.
4. Разделение ростеров исключает циркулярность: заявления не зависят от рёбер; рёбра зависят от связей и структурных численностей — состояние вычислимо однозначно.

### 5.4 Пороги и дизъюнктный подсчёт

1. **Дизъюнктный подсчёт.** Для групп $X, Y$:
$$U_{X \Rightarrow Y} = \big|\{\,p \in R_{str}(X):\ \exists\, q \in R_{str}(Y) \setminus R_{str}(X),\ \text{связь } (p,q) \text{ активна}\,\}\big|$$
Связи считаются только во **внешнюю** часть контрагента. Группа не может корроборировать привязку своими собственными членами: co-membership не засчитывается, «бесплатный въезд» через декларации закрыт; поглощение требует живых связей в участников вне присоединяющейся группы.
2. **Пороги сторон** — от численности самой стороны и общих характеристик пары:
$$f(m) = \begin{cases} 0.5, & m < 30 \\ 0.05 + 0.45 \cdot 1.5^{-\log_{10}(m/30)}, & 30 \le m \le 10^4 \\ 0.05 + 0.1618 \cdot 4^{-\log_{10}(m/10^4)}, & m > 10^4 \end{cases}$$
$$\gamma(\rho) = \min\big(1,\ f(\mathrm{avg}) + c\,(\rho - 1)\big),\quad c = 0.25;\qquad \mathrm{floor}(m) = \min(\lfloor m/2.5 \rfloor,\ 4500)$$
$$t_{big} = \min\Big(|big|,\ \max\big(\lfloor f \cdot |big| \rfloor,\ \mathrm{floor}(\mathrm{avg})\big) + 1\Big)$$
$$t_{small} = \min\Big(|small|,\ \max\big(\lfloor f \cdot |small| \rfloor,\ \lfloor \gamma \cdot |small| \rfloor,\ \mathrm{floor}(\mathrm{avg})\big) + 1\Big)$$
где $small, big$ — стороны по численности, $\rho = |big|/|small|$, $\mathrm{avg} = (|X|+|Y|)/2$.
3. **Пара $(X, Y)$ проходит** ⟺ $U_{X \Rightarrow Y} \ge t_X$ и $U_{Y \Rightarrow X} \ge t_Y$.
4. **Инварианты:** (i) при 100% взаимных **внешних** связях пара проходит при любых размерах; (ii) $t_X \le |X|$ по построению; (iii) равные пары: $t = \min(m, \max(\lfloor f\,m \rfloor, \mathrm{floor}(m)) + 1)$; (iv) при $\rho = 1$, $m < 30$: $t = \lfloor m/2 \rfloor + 1$ — порог пары равен внутренней когезии L0; (v) асимметрия — не запрет, а цена: с ростом $\rho$ требование к малой стороне растёт до единогласия.

### 5.5 Живое ребро (устойчивое правило)

Ребро $X \to H$ (группа $X$ — ребёнок $H$) живо в текущем состоянии ⟺ выполнены одновременно:

- **(C1) Согласие — кворум деклараций:** не менее $\lfloor |X|/2 \rfloor + 1$ участников $R_{str}(X)$ имеют свежие декларации в $H$;
- **(C2) Корроборация — пары со всеми сёстрами:** для каждого живого ребёнка $Y \in \mathrm{children}(H) \setminus \{X\}$ пара $(X, Y)$ проходит (§5.4.3);
- **(C3) Топология:** граф детей $H$ (рёбра — проходящие пары) связен; при $k \ge 3$ детей — без мостов;
- **(C4) Уровень:** $L(X) < L(H)$; изолят не может быть ребёнком (нет уровня); родитель имеет $\ge 2$ живых детей.

*Пояснения.* (a) Согласие всегда позитивно и индивидуально отзываемо: отзыв декларации падает в кворум — ребро отпадает через окно (§5.7). (b) Контроль стороны $H$ неявный: парные пороги требуют живых связей её структурных членов в $X$ (без их сотрудничества пара не проходит), а члены $H$ вольны отзывать собственные декларации. (c) Условие $\ge 2$ детей — структурно: родитель одного ребёнка не образует иерархии.

### 5.6 Бутстрап

**Изолят $H$ активируется**, когда существует множество кандидатов $S$ — групп с выполненным **C1-кворумом** в $H$ ($\lfloor |X|/2 \rfloor + 1$ деклараций от $R_{str}(X)$), — такое что:

1. $|S| \ge 2$;
2. все пары из $S$ проходят (§5.4.3, дизъюнктно);
3. граф кандидатов (рёбра — проходящие пары) связен; при $|S| \ge 3$ — без мостов.

Активация: $\mathrm{children}(H) = S$; $R_{str}(H) = \bigcup_{X \in S} R_{str}(X)$; $L(H) = 1 + \max_{X \in S} L(X)$; **фриз $T_f$** с момента активации. Первые дети сообщества — декларирующие взаимосвязанные L0: условия между ними воспроизводят пороговые условия слияния равных групп.

### 5.7 Гистерезис, фриз, динамика

1. **Активация ребра.** Условия C1–C4 (для нового ребёнка $X$ к живому $H$ — включая пары $X$ со всеми текущими детьми и топологию после добавления) непрерывно выполняются в течение $T_{hold}$ — затем ребро активируется. Клиенты обязаны уведомлять членов затронутых групп в течение всего окна.
2. **Деактивация.** Провал C1 (кворум упал — отзывы деклараций, гашение) держится окно $T_{hold}$ (ремонт) — затем ребро $X \to H$ отпадает: $X$ освобождается (прочие родители сохраняются), $H$ перепроверяется без $X$.
3. **Распад родителя.** Провал C2/C3 (пара детей умерла, топология разорвалась) → статус «ремонт» $H$ до конца следующей эпохи; безуспешно → $H$ распускается (дети освобождаются, прочие родители сохраняются); каскад — не более одного уровня за эпоху.
4. **Фриз.** Вершина $H$ после активации (и новый родитель после бутстрапа) в течение $T_f$ **не может быть ребёнком** (не может привязываться вверх); принимать детей — может. Фриз — единственное ограничение участия: подъём на уровень требует $\ge T_{hold} + T_f$ (анти-«накачка»). **Дети не блокируются ничем и никогда**: ни фризом родителя, ни гистерезисом чужих рёбер, ни параллельными привязками.
5. **Параллелизм.** Группа может одновременно быть кандидатом/ребёнком любого числа родителей; каждая привязка независима (мультиродительство — штатное состояние DAG).

### 5.8 Эпохальная перепроверка

**Привязка — эфемерное состояние:** валидность каждого ребра — свойство текущей эпохи.

1. Каждую эпоху — полный восходящий пересчёт: валидность всех L0 (§4.4); для каждого родителя — C1 для всех детей, C2 между всеми парами детей, C3, C4; уровни пересчитываются после применения изменений. Инкрементальные вычисления допустимы («грязные» пометки по разрывам, распадам, отзывам деклараций, событиям состава) при совпадении результата с полным пересчётом.
2. Пороги всегда пересчитываются по **текущим** структурным численностям: порог, выполненный при привязке, может стать невыполнимым — штатный механизм. Стоимость и риск удержания инъецированных связей рекуррентны.
3. Дети распущенного родителя немедленно могут инициировать новые привязки (в т.ч. к бывшим «дедам» — при соблюдении C4).

### 5.9 Уровни и ацикличность

1. $L(\mathrm{L0}) = 0$; $L(H) = 1 + \max_{C \in \mathrm{children}(H)} L(C)$; изолят — без уровня. Уровень — метаданные, не критерий доверия.
2. **Ацикличность — теорема:** ребро требует $L(X) < L(H)$, поэтому взаимные рёбра $X \to H$ и $H \to X$ невозможны.
3. **Динамика уровней.** Отпадение высоких детей понижает $L(H)$; рёбра, нарушившие C4, деактивируются через своё окно — инвариант уровней восстанавливается каскадом не быстрее одного уровня за эпоху. Ожидаемая глубина при средней ширине вершины $\bar k \sim 5\text{–}10$: $D \approx \log_{\bar k}(P/\overline{|L0|})$ — 9–12; глубина — путь, а не свойство узла.

### 5.10 Возражения и выход

1. **Лёгкое возражение** — отзыв декларации (`G-LEAVE`): падает кворум C1, ребро отпадает через окно; связи не страдают.
2. **Тяжёлое возражение** — `BREAK` (разрыв + яд, §3.2).
3. **Выход группы из родителя** — организованный массовый отзыв деклараций членами $X$ до падения кворума C1; отдельного протокольного события не существует.

### 5.11 Механизм изоляции ботов

Бот-кластер может свободно декларировать любые принадлежности и создавать изоляты, но: декларации не дают иерархии (§5.3); корроборация требует внешних живых связей, которых у ботов нет; кворумы L0 контролируются людьми; дизъюнктный подсчёт исключает корроборацию co-membership. Стоимость включения ботов в человеческую иерархию остаётся $\approx t$ живых человеческих связей — рекуррентная.

### 5.12 Мотивация социальных связей

Алгоритм не регламентирует, какие узлы подтверждать. Система мотивирует установку реальных связей; предполагается, что у людей достаточно реальных связей, чтобы граф связался естественным образом.

## 6. Проверка и потребление доверия

1. **Доказательство членства.** Участник предъявляет: активные L0 (подпись вызова + свежая само-аттестация) и путь по рёбрам «ребёнок → родитель» до корня; в DAG достаточно одного пути в доверенное множество верификатора. Декларации в доказательстве не участвуют — они заявления, а не носители доверия.
2. **Субъективная оценка.** Доверенное множество — транзитивное замыкание родителей его L0 (плюс политика: размер, возраст, отсутствие аномалий §7.4). Глобального флага «человек» не существует.
3. **Практическая картина.** Реальные связи связывают людей в гигантский компонент; бот-кластеры без человеческих связей остаются изолированными мелкими компонентами (их изоляты и декларации — шум без структуры).
4. **Непересечение множеств** — условное следствие: бот не входит в человеческую иерархию, пока его группа не пройдёт парные пороги с человеческими детьми (живые связи); мультиродительство этому не помогает.

## 7. Защитные механизмы

### 7.1 Гистерезис привязок

$T_{hold}$ — окно выдержки условий перед активацией ребра и окно ремонта перед деактивацией: время для уведомлений, отзывов деклараций, разрывов и дороста связей. Подавляет флаппинг на пороговых границах. $T_f$ — задержка подъёма вершины вверх.

### 7.2 Распад связей и яд

Окно жизни $T_{1/2}/(1+N)$ с линейным стекированием, конечными сроками меток и перетиранием перемирием (§3): неподдерживаемые связи исключаются из всех порогов; распад каскадно влечёт перепроверку членств и привязок (§5.8). Яд конечен; перемирие — мгновенный путь аннулирования собственных меток пары.

### 7.3 Локализация угнанных аккаунтов и ботов

1. **Угон.** Друзья публикуют `BREAK` и `L0-EXPEL` (кворум). Разрывы: $N$ растёт → окна сжимаются в $1+N$ раз; обновления требуют подписей друзей; метки, созданные друзьями, угонщик **не может аннулировать** (перетирание требует их подписей). Исключение удаляет из L0 немедленно. Угонщик может отозвать декларации жертвы (`G-LEAVE`) — кворумы упадут, рёбра отвалятся; восстановление — новыми декларациями после возврата контроля (лёгкий, обратимый вред). При $T_{1/2}=12$ мес. и $N=6$ — полная изоляция за ≈1.7 мес.
2. **Честное восстановление.** Владелец возвращает контроль: личная переверберация → друзья подписывают `LINK` (метки аннулируются, экземпляры чистые) → декларации возобновляются — без «штрафа переживания».
3. **Боты.** Не проходят порогов без человеческих связей (§5.11); множества людей и ботов остаются непересекающимися в пределах допущений §1.3.

### 7.4 Обнаружение аномалий (публичный анализ)

Все эвристики — advisory (вне консенсуса):

1. **Churn:** циклы `LINK/BREAK`; осцилляции `BREAK↔LINK` одной пары.
2. **Каскадные разрывы** против одного pk; резкое сжатие окон.
3. **Перемирия:** массовые `LINK` сразу после каскада разрывов («прощение-фишинг»).
4. **Декларационные паттерны:** синхронные массовые `G-DECLARE/G-LEAVE`; спам изолятов; декларационные набеги на чужие сообщества (не влияют на пороги, но видны); namespace-спуфинг дескрипторов.
5. **Звёздные топологии** вокруг pk; плотность между компонентами (пробы бот-кластеров).
6. **Распределения степеней/плотности** против размера (люди — small-world; фабрики — регулярность).
7. **Синхронность операций** (`LINK/BREAK/DECLARE/ATT`).
8. **Динамика L0:** синхронные `JOIN/EXPEL`, текучесть ростеров.
9. **Накачка уровней**, аномальные глубины, вершины без прироста структурной численности.
10. **DAG-специфика:** штормы параллельных привязок, близнецы-родители.
11. Паттерны `memo`-полей разрывов.

## 8. Криптография

1. **Подписи:** Ed25519 (pk — 32 Б, подпись — 64 Б); интерфейс событий допускает постквантовые схемы.
2. **Общий секрет:** $s_{uv} = \mathrm{HKDF}(\mathrm{X25519}(x_u, pk_v))$ — опциональный защищённый канал между знакомыми (уведомления о гистерезисных окнах, запросы обновлений, координация деклараций). Канал не источник истины.
3. **Хеши:** BLAKE3, доменное разделение.
4. **Канонизация:** детерминированный CBOR; лексикографический порядок байтов.
5. **Объёмы:** `LINK` ≈ 130 Б; `BREAK`/`G-DECLARE`/`G-LEAVE`/`L0-ATT` ≈ 100 Б; `L0-GENESIS` на 30 человек ≈ 3 КБ. Декларации добавляют ~10⁸–10⁹ событий/год. Шардинг по эпохам, архив-узлы, чекпойнты.

| $10^8$ | 0.051 | 5063204 | 5% |

## 10. Ограничения и открытые вопросы

1. **Namespace.** Дескриптор — публичная метка; имперсонация имён не решаема без властей. Идентичность сообщества — структура (привязанные дети), не имя. Сигнал честности — размер и возраст структурного ростера.
2. **Многоличность.** Не детектируется принципиально; смягчения — стоимость реальных связей на каждый ключ, эвристики §7.4.
3. **Публичность согласия.** Декларации публичны: видно, кто состоит в каких сообществах. Плата за позитивное отзываемое согласие; приватизация — §11.
4. **Мажоритарная жёсткость.** Привязка группы $X$ требует деклараций большинства $R_{str}(X)$: индивидуум не может «вступить в сообщество» без большинства своей базовой группы. Осознанное следствие групповой природы протокола; возможен отдельный режим индивидуальных деклараций без структурной привязки (сознательно слабее по доверию).
5. **Лестница масштабов.** $\gamma(\rho)$ делает привязку малой группы к большой почти единогласной для малой и дорого-процентной для большой: вливание малых кластеров в гигантские сообщества напрямую нецелесообразно — рост через промежуточные уровни (по дизайну).
6. **Спам изолятов.** Декларации permissionless: возможны миллионы пустых групп. Ограничители: антиспам субстрата, гашение, нулевое влияние на пороги. Журнальная нагрузка — вопрос реализации.
7. **Грифинг ядом.** Каскад разрывов разных лиц сжимает окна; ограничители — взаимность меток, конечность, перемирие. Остаточный риск признан (§10.8: «прощение-фишинг»).
8. **Угон и клиентские политики.** Угнавший может отзывать декларации и рвать связи жертвы; не может аннулировать чужие метки. Требования к реализациям: явные подтверждения всех операций, предупреждения о контрагентах с историей разрывов.
9. **Сложность вывода рёбер.** Полный пересчёт — $O(\sum_H k_H^2 + |E_{links}| \cdot D)$ за эпоху; обязательны индексы по декларациям (кандидаты на ребёнка/родителя) и инкрементальность.
10. **Управление параметрами.** Изменение глобальных параметров = форк; governance не специфицирован.
11. **Приватность.** Граф и декларации публичны; путь приватизации — §11.

## 11. Дальнейшее развитие: приватность через ZKP

*(Не входит в базовую версию.)*

**Мотивация.** Публичный граф и публичные декларации — тяжёлый компромисс приватности. ZK-версия прячет, кто с кем связан, составы групп и принадлежности, сохраняя публичную проверяемость порогов, численностей и привязок.

**Эскиз:** обязательства Педерсона; деревья Меркла ростеров; публичны только корни, уровни и численности; нуллификаторы против двойного подсчёта; доказательства связей, деклараций и кворумов; рекурсивная агрегация.

### 12.1 C++ — машина состояний пары (§3)

```cpp
// =====================================================================
// PoSoc — эталонная машина состояний пары: LINK / BREAK / яд / распад.
// Замещение экземпляров, ПЕРЕТИРАНИЕ разрывов событием LINK, метки яда
// с линейным стекированием T/(1+N) и конечным сроком, необратимый распад.
// =====================================================================
#include <algorithm>
#include <iostream>
#include <map>
#include <set>
#include <string>
#include <utility>
#include <vector>

namespace posoc { namespace lifecycle {

using Pk   = std::string;
using Pair = std::pair<Pk, Pk>;              // нормализовано: first < second

struct Mark {
    Pair   pair;       // чей это разрыв
    Pk     against;    // кого травит
    double from;       // t_b
    double until;      // min(t_c + T, перемирие); активна на [from, until)
};

class Registry {
public:
    explicit Registry(double halfLife) : T_(halfLife) {}

    void link(const Pk& u, const Pk& v, double t) {
        const Pair p = norm(u, v);
        for (Mark& m : marks_)                       // ПЕРЕТИРАНИЕ разрывов пары
            if (m.pair == p && m.until > t) m.until = t;
        instance_[p] = t;
    }

    bool breakLink(const Pk& breaker, const Pk& other, double t) {
        const Pair p = norm(breaker, other);
        auto it = instance_.find(p);
        if (it == instance_.end() || it->second > t) return false;
        if (t >= decayOf(breaker, other, it->second)) return false;
        const double tc = it->second;
        instance_.erase(it);
        marks_.push_back({p, other, t, tc + T_});
        return true;
    }

    int N(const Pk& pk, double t) const {
        int n = 0;
        for (const Mark& m : marks_)
            if (m.against == pk && m.from <= t && t < m.until) ++n;
        return n;
    }
    double window(const Pk& u, const Pk& v, double t) const {
        return T_ / (1.0 + N(u, t) + N(v, t));
    }
    double decayTime(const Pk& u, const Pk& v) const {
        auto it = instance_.find(norm(u, v));
        return it == instance_.end() ? -1.0 : decayOf(u, v, it->second);
    }
    bool active(const Pk& u, const Pk& v, double t) const {
        auto it = instance_.find(norm(u, v));
        return it != instance_.end() && it->second <= t &&
               t < decayOf(u, v, it->second);
    }

private:
    static Pair norm(const Pk& u, const Pk& v) {
        return u < v ? Pair{u, v} : Pair{v, u};
    }
    double decayOf(const Pk& u, const Pk& v, double tc) const {
        std::set<double> pts{tc, tc + T_};
        for (const Mark& m : marks_) {
            if (m.against != u && m.against != v) continue;
            if (m.from  > tc && m.from  <= tc + T_) pts.insert(m.from);
            if (m.until > tc && m.until <= tc + T_) pts.insert(m.until);
        }
        std::vector<double> seg(pts.begin(), pts.end());
        for (size_t i = 0; i + 1 < seg.size(); ++i) {
            const double w    = window(u, v, seg[i]);
            const double cand = std::max(seg[i], tc + w);
            if (cand < seg[i + 1]) return cand;
        }
        return tc + T_;
    }

    double T_;
    std::map<Pair, double> instance_;
    std::vector<Mark> marks_;
};

}} // namespace posoc::lifecycle

int main() {
    using namespace posoc::lifecycle;
    const double T = 12.0;
    auto yn = [](bool b) { return b ? "да" : "нет"; };

    std::cout << "== Яд, перемирие, спасение выживающей связи ==\n";
    {
        Registry r(T);
        r.link("a", "b", 0); r.link("b", "c", 0);
        r.breakLink("a", "b", 2);
        std::cout << "t=3:  N_b=" << r.N("b", 3)
                  << ", окно b-c=" << r.window("b", "c", 3)
                  << ", распад b-c в t=" << r.decayTime("b", "c") << "\n";
        r.link("a", "b", 4);                       // ПЕРЕМИРИЕ
        std::cout << "t=5:  N_b=" << r.N("b", 5)
                  << ", окно b-c=" << r.window("b", "c", 5)
                  << ", распад b-c в t=" << r.decayTime("b", "c")
                  << " (спасена), распад a-b в t=" << r.decayTime("a", "b") << "\n";
    }

    std::cout << "\n== Без перемирия распад необратим ==\n";
    {
        Registry r(T);
        r.link("a", "b", 0); r.link("b", "c", 0);
        r.breakLink("a", "b", 2);
        std::cout << "b-c: t=5.9 " << yn(r.active("b", "c", 5.9))
                  << ", t=6.1 " << yn(r.active("b", "c", 6.1)) << "\n";
        std::cout << "BREAK(c->b) в t=8 принят: " << yn(r.breakLink("c", "b", 8)) << "\n";
        r.link("a", "b", 7);
        std::cout << "после перемирия a-b b-c активна: " << yn(r.active("b", "c", 8)) << "\n";
        r.link("b", "c", 9);
        std::cout << "после LINK(b,c) b-c активна: " << yn(r.active("b", "c", 10)) << "\n";
    }

    std::cout << "\n== Свои метки не стекируются, чужие - да ==\n";
    {
        Registry r(T);
        r.link("a", "b", 0);
        r.breakLink("a", "b", 1); r.link("a", "b", 2);
        r.breakLink("a", "b", 3); r.link("a", "b", 4);
        std::cout << "осцилляция a-b: N_b(5)=" << r.N("b", 5) << " (не более 1)\n";
    }
```

```python
#!/usr/bin/env python3
# PoSoc — эталонная машина состояний пары (§3).
from typing import Dict, List, Optional, Tuple

Pk = str
Pair = Tuple[str, str]


class Mark:
    __slots__ = ("pair", "against", "frm", "until")

    def __init__(self, pair, against, frm, until):
        self.pair, self.against, self.frm, self.until = pair, against, frm, until


class Registry:
    def __init__(self, half_life: float):
        self.T = half_life
        self.instance: Dict[Pair, float] = {}
        self.marks: List[Mark] = []

    @staticmethod
    def _norm(u, v) -> Pair:
        return (u, v) if u < v else (v, u)

    def link(self, u, v, t: float) -> None:
        p = self._norm(u, v)
        for m in self.marks:                      # ПЕРЕТИРАНИЕ
            if m.pair == p and m.until > t:
                m.until = t
        self.instance[p] = t

    def break_link(self, breaker, other, t: float) -> bool:
        p = self._norm(breaker, other)
        tc = self.instance.get(p)
        if tc is None or tc > t or t >= self._decay_of(breaker, other, tc):
            return False
        del self.instance[p]
        self.marks.append(Mark(p, other, t, tc + self.T))
        return True

    def N(self, pk, t: float) -> int:
        return sum(1 for m in self.marks
                   if m.against == pk and m.frm <= t < m.until)

    def window(self, u, v, t: float) -> float:
        return self.T / (1.0 + self.N(u, t) + self.N(v, t))

    def decay_time(self, u, v) -> Optional[float]:
        tc = self.instance.get(self._norm(u, v))
        return None if tc is None else self._decay_of(u, v, tc)

    def active(self, u, v, t: float) -> bool:
        tc = self.instance.get(self._norm(u, v))
        return tc is not None and tc <= t and t < self._decay_of(u, v, tc)

    def _decay_of(self, u, v, tc: float) -> float:
        pts = {tc, tc + self.T}
        for m in self.marks:
            if m.against not in (u, v):
                continue
            if tc < m.frm <= tc + self.T:
                pts.add(m.frm)
            if tc < m.until <= tc + self.T:
                pts.add(m.until)
        seg = sorted(pts)
        for s1, s2 in zip(seg, seg[1:]):
            cand = max(s1, tc + self.window(u, v, s1))
            if cand < s2:
                return cand
        return tc + self.T


if __name__ == "__main__":
    r = Registry(12.0)
    r.link("a", "b", 0); r.link("b", "c", 0)
    r.break_link("a", "b", 2)
    print("яд: N_b(3) =", r.N("b", 3), "распад b-c:", r.decay_time("b", "c"))
    r.link("a", "b", 4)                            # перемирие
    print("после перемирия: N_b(5) =", r.N("b", 5),
          "распад b-c:", r.decay_time("b", "c"), "(спасена)")
```

### 12.4 C++ — выводитель привязок (§5)

```cpp
// =====================================================================
// PoSoc — эталонный выводитель привязок: дизъюнктный подсчёт, пороги,
// кворумы деклараций, бутстрап, связность/мосты, уровни.
// =====================================================================
#include <algorithm>
#include <cmath>
#include <functional>
#include <iostream>
#include <map>
#include <set>
#include <string>
#include <vector>

namespace posoc {

using Pk    = std::string;
using Link  = std::pair<Pk, Pk>;
using Links = std::set<Link>;

const double EPS = 1e-9;
const double C   = 0.25;

double fCurve(double m) {
    if (m < 30.0) return 0.5;
    if (m <= 1e4) return 0.05 + 0.45  * std::pow(1.5, -std::log10(m / 30.0));
    return           0.05 + 0.1618 * std::pow(4.0, -std::log10(m / 1e4));
}
int flr(double m) { return std::min<int>(int(std::floor(m / 2.5 + EPS)), 4500); }
double gamma(double rho, double fa) { return std::min(1.0, fa + C * (rho - 1.0)); }

int sideThreshold(size_t selfSize, size_t otherSize) {
    const size_t s = std::min(selfSize, otherSize);
    const size_t b = std::max(selfSize, otherSize);
    const double avg = (s + b) / 2.0;
    const double fa  = fCurve(avg);
    const int    fl  = flr(avg);
    const double g   = gamma(double(b) / double(s), fa);
    const int tBig = std::min<int>(int(b),
                       std::max(int(std::floor(fa * b + EPS)), fl) + 1);
    const int tSmall = std::min<int>(int(s),
                         std::max({int(std::floor(fa * s + EPS)),
                                   int(std::floor(g  * s + EPS)), fl}) + 1);
    return (selfSize == b) ? tBig : tSmall;
}

struct Group {                                  // L0 или вершина
    std::string id;
    int level = 0;
    std::vector<Pk> roster;                     // структурный ростер
    std::set<Pk> declaredIn;                    // декларации в целевую группу
    long frozenUntil = 0;
    size_t size() const { return roster.size(); }
};

Link mk(const Pk& a, const Pk& b) { return a < b ? Link{a, b} : Link{b, a}; }
void clique(const Group& g, Links& L) {
    for (size_t i = 0; i < g.roster.size(); ++i)
        for (size_t j = i + 1; j < g.roster.size(); ++j)
            L.insert(mk(g.roster[i], g.roster[j]));
}
void biclique(const std::vector<Pk>& xs, const std::vector<Pk>& ys, Links& L) {
    for (const auto& x : xs) for (const auto& y : ys) L.insert(mk(x, y));
}

// ДИЗЪЮНКТНЫЙ подсчёт: участники X со связями в R(Y) \ R(X)
int disjointU(const Group& X, const Group& Y, const Links& L) {
    std::set<Pk> rx(X.roster.begin(), X.roster.end());
    std::set<Pk> ext;                            // внешняя часть контрагента
    for (const auto& q : Y.roster) if (!rx.count(q)) ext.insert(q);
    std::set<Pk> u;
    for (const auto& [a, b] : L) {
        if (rx.count(a) && ext.count(b)) u.insert(a);
        if (rx.count(b) && ext.count(a)) u.insert(b);
    }
    return int(u.size());
}

struct PairDiag { std::string a, b; int uAb, uBa, tA, tB; bool ok; };

bool pairPasses(const Group& X, const Group& Y, const Links& L, PairDiag* d) {
    PairDiag pd{X.id, Y.id, disjointU(X, Y, L), disjointU(Y, X, L),
                sideThreshold(X.size(), Y.size()), sideThreshold(Y.size(), X.size()),
                false};
    pd.ok = pd.uAb >= pd.tA && pd.uBa >= pd.tB;
    if (d) *d = pd;
    return pd.ok;
}

// кворум C1: |{p in roster(X): p декларировал в H}| >= floor(|X|/2)+1
bool quorum(const Group& X, const Group& H) {
    int n = 0;
    for (const auto& p : X.roster) if (H.declaredIn.count(p)) ++n;
    return n >= int(X.size()) / 2 + 1;
}

// топология: связность + отсутствие мостов (Тарьян)
bool topologyOk(const std::vector<std::vector<int>>& adj) {
    const int k = int(adj.size());
    if (k == 0) return false;
    std::vector<char> seen(k, 0);
    std::vector<int> st{0}; seen[0] = 1; size_t reach = 1;
    while (!st.empty()) {
        int u = st.back(); st.pop_back();
        for (int v : adj[u]) if (!seen[v]) { seen[v] = 1; ++reach; st.push_back(v); }
    }
    if (reach != size_t(k)) return false;
    if (k >= 3) {
        std::vector<int> disc(k, 0), low(k, 0); int timer = 0; bool bridge = false;
        std::function<void(int,int)> dfs = [&](int u, int p) {
            disc[u] = low[u] = ++timer;
            for (int v : adj[u]) {
                if (v == p) continue;
                if (!disc[v]) { dfs(v, u); low[u] = std::min(low[u], low[v]);
                                if (low[v] > disc[u]) bridge = true; }
                else low[u] = std::min(low[u], disc[v]);
            }
        };
        for (int r = 0; r < k; ++r) if (!disc[r]) dfs(r, -1);
        if (bridge) return false;
    }
    return true;
}

// Бутстрап изолята H кандидатами cands (§5.6)
struct BootReport { bool ok; std::vector<PairDiag> pairs; std::vector<std::string> err; };
BootReport bootstrap(const Group& H, const std::vector<Group>& cands, const Links& L) {
    BootReport rep;
    const int k = int(cands.size());
    std::vector<std::vector<int>> adj(k);
    for (int i = 0; i < k; ++i) {
        if (!quorum(cands[i], H))
            rep.err.push_back(cands[i].id + ": кворум деклараций не набран");
        for (int j = i + 1; j < k; ++j) {
            PairDiag d;
            if (pairPasses(cands[i], cands[j], L, &d)) {
                adj[i].push_back(j); adj[j].push_back(i);
            }
            rep.pairs.push_back(d);
        }
    }
    if (k < 2) rep.err.push_back("кандидатов меньше 2");
    if (rep.err.empty() && !topologyOk(adj))
        rep.err.push_back("граф кандидатов несвязен или содержит мосты");
    rep.ok = rep.err.empty();
    return rep;
}

// Присоединение X к живому родителю H с детьми kids (§5.5 C1-C4)
struct AttachReport { bool ok; std::vector<PairDiag> pairs; std::vector<std::string> err; };
AttachReport attach(const Group& X, const Group& H, const std::vector<Group>& kids,
                    const Links& L, long now) {
    AttachReport rep;
    if (!quorum(X, H)) rep.err.push_back("кворум C1 не набран");
    if (X.frozenUntil > now) rep.err.push_back("X заморожена");
    if (X.level >= H.level) rep.err.push_back("нарушение уровней C4");
    std::vector<Group> all = kids;
    all.push_back(X);
    const int k = int(all.size());
    std::vector<std::vector<int>> adj(k);
    for (int i = 0; i < k; ++i)
        for (int j = i + 1; j < k; ++j) {
            PairDiag d;
            if (pairPasses(all[i], all[j], L, &d)) { adj[i].push_back(j); adj[j].push_back(i); }
            rep.pairs.push_back(d);
        }
    if (!topologyOk(adj)) rep.err.push_back("топология C3 нарушена");
    rep.ok = rep.err.empty();
    return rep;
}

Group makeL0(const std::string& id, const std::string& pre, size_t n) {
    Group g; g.id = id;
    for (size_t i = 0; i < n; ++i) g.roster.push_back(pre + std::to_string(i + 1));
    return g;
}

                  << "   пара: " << (p.ok ? "проходит" : "НЕТ") << "\n";
}
```

```python
#!/usr/bin/env python3
# PoSoc — эталонный выводитель привязок (§5).
from __future__ import annotations

from dataclasses import dataclass, field
from math import floor, log10
from typing import List, Set, Tuple

EPS, C = 1e-9, 0.25


def f_curve(m: float) -> float:
    if m < 30:
        return 0.5
    if m <= 1e4:
        return 0.05 + 0.45 * 1.5 ** (-log10(m / 30))
    return 0.05 + 0.1618 * 4.0 ** (-log10(m / 1e4))


def flr(m: float) -> int:
    return min(floor(m / 2.5 + EPS), 4500)


def gamma(rho: float, fa: float) -> float:
    return min(1.0, fa + C * (rho - 1.0))


def side_threshold(self_size: int, other_size: int) -> int:
    s, b = min(self_size, other_size), max(self_size, other_size)
    avg = (s + b) / 2
    fa, fl = f_curve(avg), flr(avg)
    g = gamma(b / s, fa)
    t_big = min(b, max(floor(fa * b + EPS), fl) + 1)
    t_small = min(s, max(floor(fa * s + EPS), floor(g * s + EPS), fl) + 1)
    return t_big if self_size == b else t_small


@dataclass
class Group:
    id: str
    level: int = 0
    roster: List[str] = field(default_factory=list)
    declared_in: Set[str] = field(default_factory=set)
    frozen_until: int = 0

    @property
    def size(self) -> int:
        return len(self.roster)


Link = Tuple[str, str]


def mk(a: str, b: str) -> Link:
    return (a, b) if a < b else (b, a)


def clique(g: Group, links: Set[Link]) -> None:
    r = g.roster
    for i in range(len(r)):
        for j in range(i + 1, len(r)):
            links.add(mk(r[i], r[j]))


def biclique(xs, ys, links: Set[Link]) -> None:
    for x in xs:
        for y in ys:
            links.add(mk(x, y))


def disjoint_u(x: Group, y: Group, links: Set[Link]) -> int:
    """ДИЗЪЮНКТНЫЙ подсчёт: участники X со связями в R(Y) \ R(X)."""
    rx = set(x.roster)
    ext = set(y.roster) - rx
    u = set()
    for a, b in links:
        if a in rx and b in ext:
            u.add(a)
        if b in rx and a in ext:
            u.add(b)
    return len(u)


@dataclass
class PairDiag:
    a: str
    b: str
    u_ab: int
    u_ba: int
    t_a: int
    t_b: int
    ok: bool


def pair_passes(x: Group, y: Group, links: Set[Link]) -> PairDiag:
    d = PairDiag(x.id, y.id, disjoint_u(x, y, links), disjoint_u(y, x, links),
                 side_threshold(x.size, y.size), side_threshold(y.size, x.size), False)
    d.ok = d.u_ab >= d.t_a and d.u_ba >= d.t_b
    return d


def quorum(x: Group, h: Group) -> bool:
    return sum(1 for p in x.roster if p in h.declared_in) >= x.size // 2 + 1


def topology_ok(adj: List[List[int]]) -> bool:
    k = len(adj)
    if k == 0:
        return False
    seen, stack = {0}, [0]
    while stack:
        u = stack.pop()
        for v in adj[u]:
            if v not in seen:
                seen.add(v)
                stack.append(v)
    if len(seen) != k:
        return False
    if k >= 3:
        disc, low, timer, bridge = [0] * k, [0] * k, [0], [False]

        def dfs(u: int, p: int) -> None:
            timer[0] += 1
            disc[u] = low[u] = timer[0]
            for v in adj[u]:
                if v == p:
                    continue
                if not disc[v]:
                    dfs(v, u)
                    low[u] = min(low[u], low[v])
                    if low[v] > disc[u]:
                        bridge[0] = True
                else:
                    low[u] = min(low[u], disc[v])

        for r in range(k):
            if not disc[r]:
                dfs(r, -1)
        return not bridge[0]
    return True


def bootstrap(h: Group, cands: List[Group], links: Set[Link]):
    pairs: List[PairDiag] = []
    err: List[str] = []
    k = len(cands)
    adj = [[] for _ in range(k)]
    for i, c in enumerate(cands):
        if not quorum(c, h):
            err.append(f"{c.id}: кворум деклараций не набран")
    for i in range(k):
        for j in range(i + 1, k):
            d = pair_passes(cands[i], cands[j], links)
            if d.ok:
                adj[i].append(j)
                adj[j].append(i)
            pairs.append(d)
    if k < 2:
        err.append("кандидатов меньше 2")
    if not err and not topology_ok(adj):
        err.append("граф кандидатов несвязен или содержит мосты")
    return (not err), pairs, err


def attach(x: Group, h: Group, kids: List[Group], links: Set[Link], now: int):
    pairs: List[PairDiag] = []
    err: List[str] = []
    if not quorum(x, h):
        err.append("кворум C1 не набран")
    if x.frozen_until > now:
        err.append("X заморожена")
    if x.level >= h.level:
        err.append("нарушение уровней C4")
    allg = kids + [x]
    k = len(allg)
    adj = [[] for _ in range(k)]
    for i in range(k):
        for j in range(i + 1, k):
            d = pair_passes(allg[i], allg[j], links)
            if d.ok:
                adj[i].append(j)
                adj[j].append(i)
            pairs.append(d)
    if not topology_ok(adj):
        err.append("топология C3 нарушена")
    return (not err), pairs, err


def make_l0(gid: str, pre: str, n: int) -> Group:
    g = Group(id=gid)
    g.roster = [f"{pre}{i + 1}" for i in range(n)]
    return g

              f"U<- = {p.u_ba}/{p.t_b}   пара: {'проходит' if p.ok else 'НЕТ'}")
```
