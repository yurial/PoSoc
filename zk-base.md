# Спецификация протокола PoSoc (v0.7)

## 1. Назначение, принципы, модель угроз

### 1.1 Назначение

Цель — децентрализованная сеть доверия (**PoSoc — Proof of Social**), отличающая реальных людей от ботов/виртуальных аккаунтов и разделяющая их на непересекающиеся множества: компоненты реальных людей и изолированные компоненты ботов.

Гарантии протокола — **условные и вероятностные**: они опираются на допущения §1.2–1.3 и формулируются в терминах стоимости атаки, а не как абсолютные свойства.

### 1.2 Базовые принципы

1. **Отсутствие корневых узлов.** Нет верифицированных, привилегированных или Genesis-участников. Нейтральная инфраструктура упорядочивания событий (§2.2) не является «узлом» и не принимает решений о валидности групп.
2. **Одноранговость.** Нет валидаторов и иных ролей с полномочиями; каждый участник полностью валидирует своё состояние сам (§2.2).
3. **Субъективное локальное доверие.** Участник доверяет группам, входящим в иерархии его базовых L0-групп (§6). Изолированные компоненты графа им не доверяются.
4. **Социальная ответственность.** Предполагается, что участники не подтверждают ботов ради искусственного объединения групп. Проблема подкупа **намеренно выведена из модели угроз** (§1.3).
5. **Публичная криптография.** Все связи, ростеры и операции публичны; валидность — чистая функция публичных данных; публичность открывает **поиск аномалий** (§7.4). Приватизация через ZKP — направление развития (§11).
6. **Эфемерность структуры.** Ни связь, ни членство, ни слияние не являются однажды «купленным» фактом: всё требует поддержки и перепроверяется на текущем состоянии.
7. **Взаимность согласия.** Каждый акт доверия двусторонен: связь — две подписи; членство в L0 — само-аттестация участника плюс принятие группой; ребро слияния — двусторонний порог; **примирение (перетирание разрыва) — тоже две подписи, включая подпись разорвавшей стороны**. Односторонних утверждений о доверии не существует; односторонни только разрыв, выход, вето и отзыв.

### 1.3 Модель угроз и границы гарантий

**Противник может:** создавать неограниченное число ключей (Sybil); полностью контролировать связи между своими узлами; получать связи с людьми (встреча, обман, подкуп); похищать закрытые ключи.

**Противник не может (криптографически):** подделать подпись; создать или обновить связь без встречной подписи контрагента; включить участника в L0 без его собственной подписи (§4.1); разорвать чужую связь; **аннулировать метку яда без подписи разорвавшей стороны** — перетирание метки происходит только новым `LINK` той же пары (§3.2); удерживать членство, связь или слияние без рекуррентного подтверждения.

**Гарантии (при допущениях §1.2):**
- *Стоимость включения.* Включение ботов в человеческую иерархию требует $\approx t(A,B)$ взаимных связей с реальными людьми; стоимость линейна по порогу и **рекуррентна**.
- *Изоляция.* Компонент без человеческих связей не может слиться с человеческим: порог недостижим без людей.
- *Локализация угона.* Угнанный аккаунт отторгается тем быстрее, чем больше разрывов против него: окно связей сжимается в $1+N$ раз (§7.3); изоляция устойчива к отмыванию — угонщик не может аннулировать метки, созданные друзьями.
- *Восстановление.* Честное примирение полноценно: повторный `LINK` пары мгновенно аннулирует её метки и восстанавливает отношения; чужое недоверие снимается только временем или перемирием его автора.

**Негарантии (осознанные ограничения):** многоличность (§10.2); сговор выше порогов (§10.5); приватность графа в базовой версии (§11).

## 2. Архитектура

### 2.1 Идентичность

1. Личность — пара ключей $(x,\ pk)$, Ed25519 (§8). Секрет $x$ никогда не публикуется.
2. Отдельной «регистрации» нет: ключ существует, если фигурирует хотя бы в одном валидном событии. Sybil-устойчивость обеспечивает не реестр, а социальный граф: ключ без связей не входит ни в одну группу.
3. Один человек может владеть несколькими ключами (§10.2).

### 2.2 Одноранговая сеть и публичный журнал

**Валидаторов нет.** Протокол не определяет ролей с полномочиями. Сеть одноранговая.

1. **Распространение.** События распространяются gossip-протоколом между равными узлами.
2. **Полная локальная валидация.** Каждый участник полностью валидирует своё состояние сам: проверяет подписи и каноническую форму всех событий, детерминированно вычисляет производное состояние (§2.3) и перепроверяет валидность групп. Валидации «чужими руками» не существует; ничьё одобрение не требуется и не предусмотрено.
3. **Некорректные события.** Журнал может содержать мусор — субстрат упорядочивания не проверяет правила PoSoc. Каждый узел **детерминированно игнорирует**: события с неверными подписями, неканонической формой, дубликаты по содержимому (повторная публикация — no-op) и события с неприменимым переходом (например, `BREAK` без активной связи, `L0-JOIN` со старой версией состава). Правила игнорирования — часть спецификации: результат вычисления состояния одинаков у всех узлов.
4. **Базовая модель узла — полная реплика журнала.** Проверка «своего» состояния на практике требует всего журнала. Масштабирование — верифицируемые чекпойнты (снапшот + хеш-цепочка к генезису), проверяемые локально без доверия к публикатору.
5. **Субстрат упорядочивания.** Журнал требует тотального порядка и финальности. Допустим любой механизм (существующая цепочка, федеративный лог, специализированный консенсус): он **не интерпретирует правила PoSoc** и не влияет на валидность групп — только на порядок и доступность событий. Требования: append-only, детерминированный тотальный порядок, финальность, доступность данных, разумная устойчивость к цензуре; антиспам-политика — за субстратом.

*Пояснение.* Разделение ответственности: консенсус отвечает на вопрос «в каком порядке произошли события», PoSoc — «что из этого следует». Все выводы каждый участник делает сам.

### 2.3 События и производное состояние

| Событие | Подписи | Назначение |
|---|---|---|
| `LINK(u, v)` | обе стороны | новый экземпляр связи пары; замещает прежний и **перетирает разрывы пары** (§3.1–3.2) |
| `BREAK(u → v)` | $u$ | разрыв текущего экземпляра; метка яда против $v$ до истечения или перемирия (§3.2) |
| `VETO(pk, ctx)` | $pk$ | возражение против слияния (§5.5) |
| `L0-GENESIS(ID, roster)` | каждый член ростера (само-аттестации) | создание группы (§4.2) |
| `L0-ATT(G, P, epoch)` | $P$ | само-аттестация членства (§4.2) |
| `L0-JOIN(G, ver, P)` | $P$ + вуши кворума членов | приём члена (§4.2) |
| `L0-LEAVE(G, ver, P)` | $P$ | выход члена (§4.2) |
| `L0-EXPEL(G, ver, P)` | кворум членов кроме $P$ | исключение члена (§4.2) |
| `EXIT-G(C, P)` | кворум членов $C$ | выход дочерней группы из родителя (§5.7) |
| `PROPOSE(M, ctx)` | инициатор + PoW | предложение слияния (§5.5) |
| `WITHDRAW(ctx)` | инициатор | отзыв предложения |
| `MERGE-OK(ctx)` | любой участник | якорь финализации слияния |

Взаимные операции (`LINK`, `L0-GENESIS`, `L0-JOIN`, `L0-EXPEL`) публикуются в завершённом виде — церемония согласования происходит вне журнала (личная встреча, канал §8.2). Односторонние (`BREAK`, `VETO`, `WITHDRAW`, `MERGE-OK`, `L0-ATT`, `L0-LEAVE`) публикуются мгновенно. `MERGE-OK` ничего не «утверждает»: родитель создаётся, только если условия §5.5.3 выполнены на момент якоря.

**Производное состояние** (чистая функция журнала, вычисляемая последовательной обработкой): текущие экземпляры связей, метки яда и $N_x$, моменты распада, составы L0 (версии, активные ростеры, свежесть аттестаций), DAG иерархии (множества детей, уровни, ростеры, фризы), статусы перепроверки. Просроченные и разорванные связи, пассивные члены исключаются из активного состояния, но сохраняются в архиве (анализ §7.4).

### 2.4 Канонизация

- Детерминированная сериализация (канонический CBOR: ключи отсортированы); пары ключей в событиях связей упорядочиваются лексикографически; самосвязи запрещены.
- $\mathrm{sort}(\cdot)$ — лексикографический порядок байтовых строк; $pk$ — raw-байты.
- $H$ — BLAKE3 с доменным разделением по типам объектов (§8).
- Все округления в порогах (§5.3) выполняются с допуском $\lfloor x + \varepsilon \rfloor$, $\varepsilon = 10^{-9}$ — для идентичности результатов на разных платформах на целых границах.

## 3. Связи

### 3.1 Экземпляры связей: установление, обновление, перемирие

1. Связь — отношение между парой ключей $(u, v)$. В каждый момент у пары существует **не более одного актуального экземпляра**.
2. Событие `LINK(u, v)` (подписи обеих сторон) создаёт **новый экземпляр** с моментом создания $t_c$. Установление и обновление — **единая операция**: более свежий экземпляр **замещает** прежний; тот уходит в архив и перестаёт учитываться во всех подсчётах. Обновлённый экземпляр не наследует возраст прежнего: окно жизни (§3.3) отсчитывается заново.
3. **Перетирание разрывов.** Событие `LINK(u, v)` **перетирает предшествующие разрывы этой же пары**: все активные метки яда, созданные событиями `BREAK(u → v)` и `BREAK(v → u)`, аннулируются в момент события (§3.2). Новый экземпляр пары чист от её **собственных** разрывов; его окно сужается только метками, созданными разрывами с третьими лицами. Повторное установление после распада — тот же механизм: пара начинает с чистого листа относительно собственной истории.
4. **Машина состояний пары.** Состояние пары в момент $t$ определяется последними событиями пары:
   - **живая** — последний экземпляр не разорван, не замещён и не распался (§3.3);
   - **разорванная** — последним событием был `BREAK`: экземпляра нет, метка активна;
   - **распавшаяся** — экземпляр умер по окну жизни: экземпляра нет, меток от этой пары нет;
   - **нейтральная** — ни экземпляра, ни активной метки.

   Переходы: `LINK` → живая (из любого состояния; из разорванной — с перетиранием метки); `BREAK` → разорванная (только из живой); истечение окна → распавшаяся; истечение метки → нейтральная. Истечение или перетирание метки **не** оживляет распавшуюся пару — только её собственный `LINK`.

### 3.2 Разрыв и яд (Poison)

**Разрыв.** `BREAK(u → v, memo)` — одностороннее событие $u$, применимое только к **живому** экземпляру пары (просроченную или распавшуюся связь рвать нечего — событие игнорируется):

1. Разрыв немедленно уничтожает текущий экземпляр; `memo` — необязательный публичный комментарий (анализ §7.4).
2. Разрыв создаёт **метку яда**:
$$\mu = (\text{пара}: (u,v),\ \text{против}: v,\ t_b,\ \text{активна на } [t_b,\ t_{end}))$$
$$t_{end} = \min\big(t_c(\ell) + T_{1/2},\ t_{\mathrm{relink}}\big)$$
где $\ell$ — разорванный экземпляр (создан в $t_c$), $t_{\mathrm{relink}}$ — момент ближайшего последующего `LINK(u, v)` (если его нет — $\infty$). Срок метки ограничен базовым окном разорванной связи ($\le T_{1/2}$ с момента разрыва); **перемирие обрезает его раньше**.
3. Журнал неизменяем: **перетирание — семантика производного состояния** (усечение интервала активности метки); история разрывов остаётся в журнале навсегда и доступна анализу (§7.4).
4. $N_a(t)$ — число меток, активных в момент $t$ против участника $a$.

**Яд.** Окно жизни экземпляра $\ell = (a, b)$:

$$W_\ell(t) = \frac{T_{1/2}}{1 + N_a(t) + N_b(t)}$$

Скорость распада растёт **линейно с числом активных разрывов**: $N$ разрывов против участника сжимают окно всех его связей в $1+N$ раз.

**Свойства механики:**

1. **Направленность.** Травится покинутый; связи разрывающего не ускоряются.
2. **Стекирование и инвариант пары.** Метки **разных** пар суммируются: каскад из $k$ разрывов от $k$ разных людей сжимает окно в $1+k$ раз. Метки **одной** пары никогда не перекрываются: разрыв требует живого экземпляра, а следующий `LINK` пары обнуляет его метку — **не более одной активной метки на пару**, и считается она против ровно одного конца. Следствие: $N_a(t) \le \deg(a)$ — яд участника ограничен числом его знакомств.
3. **Перемирие лечит.** `LINK(u, v)` мгновенно аннулирует активные метки этой пары: $N$ обоих концов падает, и окна **всех выживающих** связей $u$ и $v$ расширяются немедленно. Новый экземпляр пары чист от её собственных разрывов. Метки третьих лиц не затрагиваются: недоверие посторонних прощается только временем (истечение $\le T_{1/2}$).
4. **Восстановление — два пути.** (а) Истечение: нормальное окно гарантированно восстанавливается не позднее $T_{1/2}$ после последнего разрыва. (б) Перемирие: метки конкретной пары аннулируются мгновенно её `LINK`. Распавшиеся связи не оживают сами — ни истечением, ни перемирием чужой пары: оживление распавшейся пары — только её собственным `LINK` (новый экземпляр, чистый от её разрывов).
5. **Отмывание недоступно.** Аннулирование метки требует `LINK` пары — подписей обеих сторон, **включая разорвавшую**. Держатель угнанного ключа не может стереть метки, созданные друзьями жертвы; создать метку можно только разорвав живую взаимную связь. Прощать может только автор недоверия.
6. **Цена грифинга.** Цикл `LINK → BREAK → LINK → …` требует подписи «жертвы» на каждый `LINK`; собственные метки пары не накапливаются (перетирание); эффект для третьих связей транзиентен и требует сотрудничества «жертвы». Скоординированный каскад разрывов от разных лиц стекируется, но каждая метка требует предшествующей взаимной связи.
7. **Каскад разрывов** против одного ключа — сильный публичный сигнал компрометации (§7.4).

*Пример ($T_{1/2} = 12$ мес.).* Пара $(a, b)$ разорвана в $t=2$ (экземпляр создан в $t=0$): метка против $b$ активна на $[2, 12)$. Связь $(b, c)$, созданная в $t=0$, получает окно $12/(1+1) = 6$ мес. и распалась бы в $t=6$. Перемирие `LINK(a, b)` в $t=4$ аннулирует метку: $N_b$ падает до 0, окно $(b, c)$ немедленно расширяется до 12 мес., распад отодвигается на $t=12$ — **выживающая связь спасена**; сама пара $(a, b)$ получает свежий экземпляр с распадом в $t=16$. Без перемирия $(b, c)$ распадается в $t=6$, и перемирие $(a, b)$ в $t=7$ её **не оживит** — нужно `LINK(b, c)`.

**Обоснование.** Разрыв — публичное свидетельство недоверия («этого участника покинул тот, кто его знал»); перемирие — публичное свидетельство отзыва того же свидетельства тем же автором. Реальные отношения допускают ссоры и примирения: протокол обязан поддерживать честное восстановление, при этом аннулировать недоверие может только его автор — подпись разорвавшей стороны. Привязка срока метки к базовому окну разорванной связи масштабирует силу свидетельства со свежестью отношений; линейное стекирование суммирует независимые свидетельства.

### 3.3 Распад (Trust Decay)

**Все связи имеют время жизни.** Экземпляр $\ell$, созданный в $t_c$, распадается в момент

$$d(\ell) = \min\big\{\tau \ge t_c:\ \tau - t_c \ge W_\ell(\tau)\big\}$$

(поскольку $W \le T_{1/2}$, распад наступает не позднее $t_c + T_{1/2}$).

1. **Активная связь** — экземпляр не разорван, не замещён и не распался. Только активные связи участвуют во всех подсчётах.
2. **Необратимость.** Распад — жёсткое отсечение: оживление пары — только новым `LINK` (новый экземпляр, чистый от разрывов пары). Истечение или аннулирование меток расширяет окна выживших экземпляров, но **не оживляет распавшиеся**: «зомби»-связей и «мигающих» групп не существует.
3. **Вычислимость.** $W$ кусочно-постоянна — меняется в моменты разрывов, истечений и **аннулирований (перемирий)** меток; $d(\ell)$ вычисляется сканированием этих моментов. Сужение окна может убить экземпляр мгновенно; расширение отодвигает момент распада выжившего экземпляра, но никогда не возвращает распавшийся. Корректность усечения: метка, усечённая в $t_r$, активна до $t_r$ — все моменты распада $< t_r$ остаются детектируемыми, моменты $\ge t_r$ пересчитываются правомерно.
4. Хранение журнала шардируется по эпохам; распад каскадно влечёт перепроверку членств и слияний (§5.6).

*Примеры* ($T_{1/2} = 12$ мес.): 1 разрыв → окно 6 мес.; 3 разрыва → 3 мес.; 7 разрывов → ≈1.5 мес.; перемирие с одним из разорвавших → $N$ падает на 1 немедленно.

### 3.4 Межгрупповые связи

$U_{A \to B}$ — множество $pk$ из активного ростера $A$, имеющих хотя бы одну **активную** связь с некоторым $pk$ из активного ростера $B$; каждый pk учитывается один раз.

## 4. Базовые группы (L0)

### 4.1 Членство: взаимный акт

1. Листовые группы — **L0**; соответствуют реальным малым группам (соседи, одноклассники, коллеги). Реальность подтверждается личными встречами.
2. **Членство участника $P$ в группе $G$ — двусторонний акт:** $P$ подписывает **само-аттестацию** — собственную принадлежность к группе; группа подписывает **принятие** — вуши членов (при приёме).
3. **Самоподпись членства обязательна и незаменима.** Ни один ростер, событие или изменение состава не могут включить $P$ без подписи $P$. Принадлежность к группе — утверждение о человеке; подтвердить его может только сам человек. Это исключает включение против воли, фабрикацию составов с чужими ключами и «заложное» членство.
4. Асимметрия входа и пребывания намеренна: **вход требует согласия самого участника, пребывание — большинства группы** (§4.2.4).

### 4.2 События жизненного цикла

Состав группы — производное состояние: свёртка событий журнала в порядке следования. Каждое событие изменения состава ссылается на **версию** состава и применяется только к текущей голове; конкурирующие события одной версии разрешаются порядком журнала. Идентификатор группы фиксируется на генезисе и не меняется.

1. **Генезис** `L0-GENESIS(ID, roster)`: ростер $4 \le n \le 30$; каждый член публикует само-аттестацию. $ID_G = H(\mathrm{sort}\{pk_i\}\ \Vert\ \texttt{epoch}_{genesis})$.
2. **Приём** `L0-JOIN(G, ver, P)`: само-аттестация $P$ + вуши от $\ge \lfloor |M|/2 \rfloor + 1$ текущих активных членов; итоговый ростер $\le 30$.
3. **Выход** `L0-LEAVE(G, ver, P)`: подпись $P$.
4. **Исключение** `L0-EXPEL(G, ver, P)`: подписи $\ge \lfloor (|M|-1)/2 \rfloor + 1$ членов, кроме $P$; подпись исключаемого **не требуется** (иначе угнанный ключ нельзя удалить). Возврат после `LEAVE`/`EXPEL` — только через `JOIN`.
5. **Само-аттестация** `L0-ATT(G, P, epoch)`: подпись $P$; действует окно $T_m$ (2 эпохи). Подтверждение — явное действие пользователя, не чаще раза в эпоху.
6. Вуши действительны бессрочно — они фиксируют факт приёма; действительность членства определяется свежестью само-аттестации и событиями выхода/исключения.

### 4.3 Состояния членства и активный ростер

1. **Активный** член — свежая само-аттестация, не выходил, не исключён. Только активные члены входят в ростер для всех подсчётов.
2. **Пассивный** — аттестация просрочена: в ростер не входит (молчаливый выход). Новая аттестация восстанавливает членство без повторных вушей, если группа существует и когезия выполняется.
3. **Покинувший/исключённый** — возврат только через `JOIN`.

*Пояснение.* Аттестационное окно делает членство поддерживаемым, а не однажды полученным — в едином духе с распадом связей и эфемерностью слияний. Просрочка — штатный бесконфликтный выход (потеря ключа, уход); `EXPEL` — инструмент против угнанных ключей, которые сами способны подписывать аттестации.

### 4.4 Валидность группы

1. $4 \le |M_{active}| \le 30$;
2. **когезия:** каждый активный член имеет активные связи (§3) не менее чем с $N = \lfloor |M_{active}|/2 \rfloor + 1$ другими активными членами.

Валидность вычисляется каждым узлом как производное состояние. Верхняя граница принудительна на уровне событий; нижняя — свойство активного ростера.

### 4.5 Ремонт и распад

Нарушение валидности → статус «ремонт» на одну эпоху: участники восстанавливают связи (**в том числе перемирием** — повторный `LINK` с аннулированием меток, §3.2), аттестуются, исключают (`EXPEL`) выпавших. Безуспешный ремонт → распад: каждая компонента активного графа связей, удовлетворяющая §4.4, пере-генезируется как **новая** L0 (новый ID, новые само-аттестации); остальные члены присоединяются к другим группам или создают новые.

*Пояснение.* Динамика состава — прямое следствие конструкции: расширение (`JOIN`) и сужение (`LEAVE` / просрочка / `EXPEL`) — локальные события, не требующие пересборки группы. Единственные «универсальные» подписи — само-аттестации: каждый подписывает только за себя.

## 5. Иерархия и N-арные слияния

### 5.1 Структура: DAG, фриз, неблокируемость детей

1. Иерархия — **направленный ациклический граф (DAG)** с рёбрами «ребёнок → родитель». Ацикличность гарантирована уровнями: $L_{parent} = \max_i L_{child_i} + 1$.
2. **Группа может иметь несколько родителей** — результат участия в нескольких слияниях, включая параллельные. Пересечения ростеров между ветвями допустимы; ростер — множество pk (дедупликация), $|G|$ публикуется явно.
3. Исходные группы при слиянии **сохраняют идентичность** и **никогда не блокируются**. Роспуск — только по итогам перепроверки (§5.6).
4. **Фриз.** Новый родитель замораживается на $T_f$: не может входить в множества новых слияний. Фриз — **единственное** ограничение участия в слияниях (анти-«накачка»: подъём на уровень ≥ $T_q + T_f$).
5. **Дочерние группы не блокируются ничем**: ни карантином, ни фризом родителя, ни наличием родителей, ни параллельными контекстами.
6. $\mathrm{roster}(P) = \bigcup_{C \in \mathrm{children}(P)} \mathrm{roster}(C)$ по уникальным pk.

### 5.2 Множество слияния, контекст, граф слияния

1. **Множество слияния** $M = \{G_1, \dots, G_k\}$, $2 \le k \le K_{max}$ ($K_{max} = 10$); все $G_i$ валидны и не заморожены; уровни произвольны.
2. **Контекст:** $\texttt{ctx} = H\big(\mathrm{sort}\{\mathrm{ID}(G_i)\ \Vert\ L_{G_i}\}\ \Vert\ \texttt{epoch}_{prop}\big)$.
3. **Граф слияния** $H_M = (M, E)$: ребро $(G_i, G_j)$ существует ⟺ выполнен порог пары (§5.3) на текущем состоянии.
4. **Условия валидности:** (a) $H_M$ связен; (b) при $k \ge 3$ — нет мостов (2-рёберно-связен); (c) **правило роста:** $|G_{new}| > \max_i |G_i|$; (d) **дедупликация:** $M$ не совпадает с множеством детей ни одного живого родителя.
5. **Блокировок нет.** Параллельные предложения с пересекающимися множествами разрешены; каждая успешная финализация независима. При $k = 3$ условие (b) эквивалентно выполнению порога для всех трёх пар; при $k = 2$ единственное ребро — мост по определению (бинарное слияние структурно хрупко, не рекомендуется как основной режим роста).

### 5.3 Порог слияния

1. **Двусторонность.** Ребро существует ⟺
$$|U_{A \to B}| \ge t_A \quad\text{и}\quad |U_{B \to A}| \ge t_B,$$
где $U$ — по §3.4, пороги сторон вычисляются от численности самой стороны и общих характеристик пары по **текущим** активным ростерам. Правило едино для всех пар, включая L0↔L0.
2. **Обозначения.** $small$, $big$ — стороны по численности, $\rho = |big|/|small| \ge 1$, $\mathrm{avg} = (|A|+|B|)/2$.
3. **Масштабная кривая:**
$$f(m) = \begin{cases} 0.5, & m < 30 \\ 0.05 + 0.45 \cdot 1.5^{-\log_{10}(m/30)}, & 30 \le m \le 10^4 \\ 0.05 + 0.1618 \cdot 4^{-\log_{10}(m/10^4)}, & m > 10^4 \end{cases}$$
Непрерывна: $f(30) = 0.5$, $f(10^4) = 0.2118$.
4. **Шкала единогласия** — цена асимметрии для малой стороны:
$$\gamma(\rho) = \min\big(1,\ f(\mathrm{avg}) + c\,(\rho - 1)\big), \qquad c = 0.25$$
Доля, требуемая от малой стороны, растёт линейно с асимметрией — до **единогласия** ($\rho \approx 3$ для малых пар, $\approx 4.8$ на больших масштабах).
5. **Пол заговора:** $\mathrm{floor}(m) = \min(\lfloor m/2.5 \rfloor,\ 4500)$.
6. **Пороги сторон** ($\min(\cdot, |X|)$ — структурная осуществимость):
$$t_{big} = \min\Big(|big|,\ \max\big(\lfloor f(\mathrm{avg}) \cdot |big| \rfloor,\ \mathrm{floor}(\mathrm{avg})\big) + 1\Big)$$
$$t_{small} = \min\Big(|small|,\ \max\big(\lfloor f(\mathrm{avg}) \cdot |small| \rfloor,\ \lfloor \gamma \cdot |small| \rfloor,\ \mathrm{floor}(\mathrm{avg})\big) + 1\Big)$$
При равенстве численностей формулы совпадают ($\gamma(1) = f$).
7. **Инварианты:** (i) при 100% взаимных связей ребро существует для пары любых размеров; (ii) $t_X \le |X|$ по построению; (iii) равные пары: $t = \min(m,\ \max(\lfloor f(m) m \rfloor, \mathrm{floor}(m)) + 1)$; (iv) при $\rho = 1$, $m < 30$: $t = \lfloor m/2 \rfloor + 1$ — порог слияния равен внутренней когезии L0; (v) асимметрия заменена ценой: поглощение требует консенсуса поглощаемых.
8. **Семантика компонентов.** $f$ — единый масштабный знаменатель (каждая сторона отдаёт сопоставимую долю); $\gamma$ — защита от вектора «дёшево купить малую группу» (цена растёт до 100%); floor — абсолютный минимум людей на среднем масштабе, клампится размером стороны.

### 5.4 Уникальность подсчёта

1. В паре $(A, B)$ каждый pk учитывается один раз.
2. pk, входящий в несколько групп $M$, учитывается независимо в каждой паре, но в ростер родителя включается один раз.
3. Участник в нескольких ветвях DAG входит в ростер каждой своей группы: ростеры суть множества pk, пороги считают pk.

### 5.5 Протокол слияния

1. **Предложение.** Инициатор (pk из $\bigcup_i \mathrm{roster}(G_i)$) публикует `PROPOSE(M, ctx)` с proof-of-work. Пре-чек условий §5.2; отказ → cooldown. Предложение ничего не блокирует.
2. **Карантин $T_q$.** Обязательная пауза (например, 7 суток; клиенты уведомляют членов затронутых групп). В течение карантина: `VETO(pk, ctx)` — лёгкое возражение (pk исключается из $U$-подсчётов ctx, связи не страдают); `BREAK` — тяжёлое возражение (разрыв + яд, §3.2); `WITHDRAW` — отзыв предложения.
3. **Якорь.** В окне $[t_{prop} + T_q,\ t_{prop} + T_q + T_a]$ любой участник публикует `MERGE-OK(ctx)`. На момент якоря проверяются все условия §5.2 **с учётом вето**. Успех → родитель: $\mathrm{ID}_{parent} = H(\mathrm{sort}\{\mathrm{ID}(C_i)\}\ \Vert\ \texttt{epoch}_{fin})$, $L_{new} = \max_i L_{G_i}+1$, ростер (дедуп), $|G_{new}|$; заморозка до $t_{anchor} + T_f$; дети получают ребро. Провал → якорь отклоняется; ctx жив до конца окна либо до `WITHDRAW`.
4. **Универсальное подписание не требуется.** Согласие выражается взаимными связями и отсутствием вето; молчание в карантине — согласие. Отсутствующий участник не блокирует слияние.
5. **Провал/закрытие.** Побочных эффектов нет. Cooldown — только за провал пре-чека.
6. **Поиск кандидатов** — анализ публичного графа: множества групп с плотностью межростерных связей, достаточной относительно порогов (§7.4).

### 5.6 Эпохальная перепроверка и жизненный цикл

**Слияние — эфемерное состояние:** валидность родителя — свойство текущей эпохи.

1. **Расписание.** Каждую эпоху — полный восходящий пересчёт: валидность всех L0 (§4.4), затем родители по возрастанию уровня. Инкрементальные вычисления обязательны совпадать с полным пересчётом.
2. **Проверка родителя:** все дети живы; $k \ge 2$; рёбра между всеми парами детей по активным связям и текущим ростерам; $H_M$ связен; без мостов при $k \ge 3$.
3. **Ремонт.** Невалидная группа — статус «ремонт» до конца следующей эпохи: участники обновляют/создают связи (**в т.ч. перемирие — §3.2**), аттестуются, пере-сертифицируют L0, выходят (§5.7).
4. **Роспуск.** После безуспешного ремонта: L0 — распад по §4.5; родитель — узел удаляется, дети теряют ребро (прочие родители сохраняются), родители распущенного перепроверяются (каскад ≤ 1 уровень за эпоху). Дети распущенного не заморожены и могут немедленно инициировать новые слияния.
5. Родитель с $k < 2$ детей распускается немедленно.
6. Замороженные родители перепроверяются на общих основаниях.
7. Пороги всегда пересчитываются по текущим численностям — штатный механизм.

### 5.7 Выход дочерней группы

1. Кворум $\lfloor |C|/2 \rfloor + 1$ подписей членов $C$ публикует `EXIT-G(C, P)`.
2. $P$ перепроверяется без $C$; $C$ сохраняет прочих родителей. Выход разрешён и во время фриза $P$.

### 5.8 Уровни

Уровень — метаданные, не критерий доверия. Накачка ограничена снизу $T_q + T_f$; ожидаемая глубина $D \approx \log_{\bar k}(P/\overline{|L0|})$ — 9–12 при $\bar k \sim 5\text{–}10$. В DAG глубина — путь, а не свойство узла.

### 5.9 Мотивация социальных связей

Алгоритм не регламентирует, какие узлы подтверждать. Система мотивирует установку реальных связей; предполагается, что у людей достаточно реальных связей, чтобы граф связался естественным образом.

## 6. Проверка и потребление доверия

1. **Доказательство членства.** Участник предъявляет активные L0 (подпись вызова + свежая само-аттестация) и путь до корня; в DAG достаточно одного пути в доверенное множество верификатора.
2. **Субъективная оценка.** Доверенное множество — транзитивное замыкание родителей его L0 (плюс политика: размер, возраст, отсутствие аномалий §7.4). Глобального флага «человек» не существует.
3. **Практическая картина.** Реальные связи связывают людей в гигантский компонент; бот-кластеры без человеческих связей остаются изолированными.
4. **Непересечение множеств** — условное следствие: бот не входит в человеческую иерархию, пока не получит $\approx t$ человеческих связей; мультиродительство в DAG этому не помогает — ребро слияния требует межгрупповых связей.

## 7. Защитные механизмы

### 7.1 Карантин

Обязательная пауза между предложением и финализацией: окно для вето, разрывов и реакции на уведомления. До истечения $T_q$ слияние не финализируется; после $T_q + T_a$ предложение закрывается.

### 7.2 Распад связей и яд

Окно жизни $T_{1/2}/(1+N)$: неподдерживаемые связи исключаются из всех порогов; отравленные — в $1+N$ раз быстрее; распад и истечение членства каскадно влекут перепроверку групп и слияний. Яд конечен (≤ $T_{1/2}$); **перемирие — мгновенный путь аннулирования собственных меток пары и расширения окон выживающих связей обоих концов** (§3.2).

### 7.3 Локализация угнанных аккаунтов и ботов

1. **Угон.** Друзья публикуют `BREAK` и `L0-EXPEL` (кворум). Разрывы: $N$ растёт → окна сжимаются в $1+N$ раз. Угонщик **не может**: обновить связи (`LINK` требует подписи друзей); **отмыть метки** (перетирание требует тех же подписей — §3.2.5); получить новые связи (согласие людей). Исключение удаляет из L0 немедленно. При $T_{1/2} = 12$ мес. и $N = 6$ — полная изоляция за ≈1.7 мес. Угонщик остаётся с изолированным ключом.
2. **Честное восстановление аккаунта.** Владелец возвращает контроль: личная переверберация → друзья подписывают новые `LINK` → метки аннулируются мгновенно, экземпляры чистые — восстановление без «штрафа переживания».
3. **Угон как инструмент яда.** Угнавший может рвать связи жертвы, отравляя её знакомых. Ограничители: аннулировать такую метку может только `LINK` с угнанным ключом — знакомый подпишет лишь после личной переверберации (и получит активную связь, которую уже контролирует сам); метки конечны (≤ $T_{1/2}$); осцилляции видны как churn (§7.4).
4. **Боты.** Не имея человеческих связей, не выполняют порогов; изолированные компоненты не могут слиться с человеческими.
5. Множества людей и ботов остаются непересекающимися в пределах допущений §1.3.

### 7.4 Обнаружение аномалий (публичный анализ)

Публичность графа — самостоятельный защитный слой. Все эвристики — advisory (вне консенсуса):

1. **Churn:** циклы `LINK/BREAK` по pk и парам; осцилляции `BREAK↔LINK` одной пары; повторные циклы (требуют сотрудничества «жертвы», но заметны).
2. **Каскадные разрывы** против одного pk — сигнал угона/компрометации; большой $N$ — резкое сжатие окон.
3. **Перемирия:** массовые `LINK` сразу после каскада разрывов («прощение-фишинг» — возможная соц. инженерия при возврате угнанного ключа); асимметричные перемирия.
4. **Звёздные топологии** вокруг pk — возможный оператор кластера.
5. **Плотность между компонентами** — пробы бот-кластеров к человеческим иерархиям.
6. **Распределения степеней/плотности** против размера группы (люди — small-world; фабрики — регулярность).
7. **Синхронность операций** (координированные `LINK/BREAK/VETO/ATT`).
8. **Динамика L0:** синхронные массовые `JOIN/EXPEL`, текучесть ростеров.
9. **Накачка уровней**, слияния без прироста численности.
10. **DAG-специфика:** штормы параллельных слияний, близнецы-родители, плотные мелкие подграфы с большим числом родителей.
11. Паттерны вето и `memo`-поля разрывов.

---

## 8. Криптография

1. **Подписи:** Ed25519 (pk — 32 Б, подпись — 64 Б); интерфейс событий допускает постквантовые схемы.
2. **Общий секрет:** $s_{uv} = \mathrm{HKDF}(\mathrm{X25519}(x_u, pk_v))$ — опциональный защищённый канал между знакомыми. Канал не источник истины: все факты фиксируются в журнале.
3. **Хеши:** BLAKE3, доменное разделение.
4. **Канонизация:** детерминированный CBOR; лексикографический порядок байтов.
5. **Объёмы:** `LINK` ≈ 130 Б; `BREAK`/`VETO`/`L0-ATT` ≈ 100 Б; `L0-GENESIS` на 30 человек ≈ 3 КБ. Шардинг по эпохам, архив-узлы, чекпойнты.

## 10. Ограничения и открытые вопросы

1. **Холодный старт и справедливость.** Минимальная L0 требует 4 участников с взаимными связями; онбординг — кластерами сообществ.
2. **Многоличность.** Не детектируется принципиально; смягчения — стоимость реальных связей на каждый ключ, эвристики §7.4.
3. **Внутригрупповой сговор в L0.** Кворумы опираются на социальную ответственность; влияние ограничено размером группы и внешними порогами.
4. **Угон и клиентские политики.** Угнавший ключ может подписывать односторонние операции жертвы и само-аттестации; **не может аннулировать созданные друзьями метки** (перетирание требует их подписей, §3.2.5). Требования к реализациям: явные подтверждения пользователя, предупреждения о контрагентах с историей разрывов, аттестация/обновление не чаще раза в эпоху.
5. **Подкуп** — вне модели; пороги защищают только от заговора ниже порога.
6. **Грифинг ядом.** Каскад скоординированных разрывов разных лиц против честного участника сжимает его окна в $1+N$ раз. Ограничители: каждая метка требует предшествующей взаимной связи; собственные метки пары не накапливаются (перетирание); метки конечны; переживаются обновлениями или перемириями. Остаточный риск — **«прощение-фишинг»**: убеждение честных участников подписать `LINK` (аннулирующий метку и создающий связь) под предлогом восстановления; смягчения — личная переверберация перед подписью, аномалии §7.4.3, клиентские подтверждения.
7. **$k = 2$** — хрупко (единственное ребро слияния).
8. **Управление параметрами.** Изменение глобальных параметров = форк; governance не специфицирован.
9. **Субстрат журнала.** Порядок, финальность, доступность, цензуроустойчивость — свойства реализации.
10. **Приватность.** Граф публичен целиком; путь приватизации — §11.
11. **Масштабирование перепроверки.** $O(|E_{links}| \cdot D)$ за эпоху; инкрементальные индексы, ленивые вычисления, проверка «по требованию».
12. **DAG-специфика.** Дублирование членств, близнецы-родители — штатны, но усложняют анализ.

## 11. Дальнейшее развитие: приватность через ZKP

*(Не входит в базовую версию.)*

**Мотивация.** Публичный граф — тяжёлый компромисс приватности. ZK-версия прячет, кто с кем связан и составы групп, сохраняя публичную проверяемость порогов, численностей и членства.

**Эскиз:** обязательства Педерсона в реестрах; деревья Меркла ростеров; публичны только $\mathrm{Root}(G)$, $L_G$, $|G|$; нуллификаторы против двойного подсчёта; парные ZKP-доказательства; рекурсивная агрегация; Poseidon/Rescue внутри схем.

**Нерешённые проблемы (блокеры):**
1. **Симметричность связи:** доказательство знания секрета фабрикуемо одной стороной; требуется совместное доказательство двух сторон об общем DH-элементе.
2. **Воспроизведение семантики §3 в ZK:** яд (метки с линейным стекированием, конечными сроками и **перетиранием перемирием**), само-аттестации, фриз, DAG, эпохальная перепроверка; публичность меток — дополнительная утечка либо схема.
3. **Устаревание обязательств** при слияниях.
4. **Многоличность** не решается и в ZK.
5. **Поиск кандидатов** без публичного графа.
6. **Масштаб** генерации доказательств; постквантовость DH-основы.

## 12. Приложение: эталонные реализации

Два эталона. **Машина состояний пары (12.1–12.3)** реализует §3: экземпляры, перетирание `BREAK` событием `LINK`, метки с линейным стекированием и конечным сроком, окна $T/(1+N)$, необратимый распад. Её выход — множество активных связей на момент — вход **верификатора слияния (12.4–12.6)**, реализующего §4–5 (пороги, граф слияния, мосты, рост, дедуп, фриз). Сигнатуры и журнал абстрагированы.

### 12.1 C++ — машина состояний пары (§3)

```cpp
// =====================================================================
// PoSoc — эталонная машина состояний пары: LINK / BREAK / яд / распад.
// Реализует §3: замещение экземпляров, ПЕРЕТИРАНИЕ разрывов событием
// LINK, метки яда с линейным стекированием T/(1+N) и конечным сроком,
// необратимый распад.
// =====================================================================
#include <algorithm>
#include <iostream>
#include <map>
#include <set>
#include <string>
#include <utility>
#include <vector>

namespace posoc { namespace lifecycle {

using Pk   = std::string;
using Pair = std::pair<Pk, Pk>;              // нормализовано: first < second

struct Mark {
    Pair   pair;       // чей это разрыв
    Pk     against;    // кого травит
    double from;       // t_b
    double until;      // min(t_c + T, перемирие); активна на [from, until)
};

class Registry {
public:
    explicit Registry(double halfLife) : T_(halfLife) {}

    // LINK(u,v): новый экземпляр; ПЕРЕТИРАЕТ разрывы этой пары —
    // активные метки BREAK(u->v) и BREAK(v->u) усекаются моментом t.
    void link(const Pk& u, const Pk& v, double t) {
        const Pair p = norm(u, v);
        for (Mark& m : marks_)
            if (m.pair == p && m.until > t) m.until = t;
        instance_[p] = t;                    // свежий экземпляр, t_c = t
    }

    // BREAK(u->v): только для живого экземпляра; метка против покинутого.
    bool breakLink(const Pk& breaker, const Pk& other, double t) {
        const Pair p = norm(breaker, other);
        auto it = instance_.find(p);
        if (it == instance_.end() || it->second > t) return false;  // рвать нечего
        if (t >= decayOf(breaker, other, it->second)) return false; // уже распалась
        const double tc = it->second;
        instance_.erase(it);
        marks_.push_back({p, other, t, tc + T_});
        return true;
    }

    int N(const Pk& pk, double t) const {    // активные метки против pk
        int n = 0;
        for (const Mark& m : marks_)
            if (m.against == pk && m.from <= t && t < m.until) ++n;
        return n;
    }

    double window(const Pk& u, const Pk& v, double t) const {
        return T_ / (1.0 + N(u, t) + N(v, t));
    }

    double decayTime(const Pk& u, const Pk& v) const {
        auto it = instance_.find(norm(u, v));
        return it == instance_.end() ? -1.0 : decayOf(u, v, it->second);
    }

    bool active(const Pk& u, const Pk& v, double t) const {
        auto it = instance_.find(norm(u, v));
        return it != instance_.end() && it->second <= t &&
               t < decayOf(u, v, it->second);
    }

private:
    static Pair norm(const Pk& u, const Pk& v) {
        return u < v ? Pair{u, v} : Pair{v, u};
    }

    // d = min{tau >= t_c : tau - t_c >= W(tau)}; W кусочно-постоянна,
    // меняется в моменты разрывов, истечений и перетираний меток.
    double decayOf(const Pk& u, const Pk& v, double tc) const {
        std::set<double> pts{tc, tc + T_};
        for (const Mark& m : marks_) {
            if (m.against != u && m.against != v) continue;
            if (m.from  > tc && m.from  <= tc + T_) pts.insert(m.from);
            if (m.until > tc && m.until <= tc + T_) pts.insert(m.until);
        }
        std::vector<double> seg(pts.begin(), pts.end());
        for (size_t i = 0; i + 1 < seg.size(); ++i) {
            const double w    = window(u, v, seg[i]);   // постоянно на [s1, s2)
            const double cand = std::max(seg[i], tc + w);
            if (cand < seg[i + 1]) return cand;         // возраст достиг окна
        }
        return tc + T_;                                 // W <= T всегда
    }

    double T_;
    std::map<Pair, double> instance_;   // пара -> t_c текущего экземпляра
    std::vector<Mark> marks_;
};

}} // namespace posoc::lifecycle

int main() {
    using namespace posoc::lifecycle;
    const double T = 12.0;                      // T_{1/2}, месяцев
    auto yn = [](bool b) { return b ? "да" : "нет"; };

    std::cout << "== Сценарий 1: яд, перемирие, спасение выживающей связи ==\n";
    {
        Registry r(T);
        r.link("a", "b", 0);
        r.link("b", "c", 0);
        r.breakLink("a", "b", 2);               // a покидает b
        std::cout << "t=3:  N_b=" << r.N("b", 3)
                  << ", окно b-c=" << r.window("b", "c", 3)
                  << ", распад b-c в t=" << r.decayTime("b", "c") << "\n";
        r.link("a", "b", 4);                    // ПЕРЕМИРИЕ: перетирание BREAK
        std::cout << "t=5:  N_b=" << r.N("b", 5)
                  << ", окно b-c=" << r.window("b", "c", 5)
                  << ", распад b-c в t=" << r.decayTime("b", "c") << " (спасена)"
                  << ", распад a-b в t=" << r.decayTime("a", "b") << "\n\n";
    }

    std::cout << "== Сценарий 2: без перемирия распад необратим ==\n";
    {
        Registry r(T);
        r.link("a", "b", 0);
        r.link("b", "c", 0);
        r.breakLink("a", "b", 2);
        std::cout << "b-c активна в t=5.9: " << yn(r.active("b", "c", 5.9))
                  << ", в t=6.1: " << yn(r.active("b", "c", 6.1)) << "\n";
        std::cout << "BREAK(c->b) в t=8 принят: " << yn(r.breakLink("c", "b", 8))
                  << " (связь уже распалась - рвать нечего)\n";
        r.link("a", "b", 7);                    // перемирие НЕ оживляет b-c
        std::cout << "после перемирия a-b (t=7) b-c активна: "
                  << yn(r.active("b", "c", 8)) << "\n";
        r.link("b", "c", 9);                    // восстановление - своим LINK
        std::cout << "после LINK(b,c) (t=9) b-c активна: "
                  << yn(r.active("b", "c", 10))
                  << ", распад в t=" << r.decayTime("b", "c") << "\n\n";
    }

    std::cout << "== Сценарий 3: свои метки не стекируются, чужие - да ==\n";
    {
        Registry r(T);
        r.link("a", "b", 0);
        r.breakLink("a", "b", 1);  r.link("a", "b", 2);
        r.breakLink("a", "b", 3);  r.link("a", "b", 4);
        std::cout << "осцилляция a-b: N_b(1.5)=" << r.N("b", 1.5)
                  << ", N_b(2.5)=" << r.N("b", 2.5)
                  << ", N_b(3.5)=" << r.N("b", 3.5)
                  << ", N_b(5)=" << r.N("b", 5)
                  << "  (не более 1 - перетирание)\n";
    }
    {
        Registry r(T);
        r.link("a", "b", 0);  r.link("c", "b", 0);  r.link("b", "d", 0);
        r.breakLink("a", "b", 2);               // метка [2, 12)
        r.breakLink("c", "b", 5);               // метка [5, 12)
        std::cout << "два разных разрыва: N_b(6)=" << r.N("b", 6)
                  << ", окно b-d(5.5)=" << r.window("b", "d", 5.5)
                  << ", b-d распалась в t=" << r.decayTime("b", "d")
                  << " (мгновенное сужение)\n";
    }
    return 0;
}
```

### 12.2 Python — машина состояний пары (§3)

```python
#!/usr/bin/env python3
# =====================================================================
# PoSoc — эталонная машина состояний пары: LINK / BREAK / яд / распад.
# =====================================================================
from typing import Dict, List, Optional, Tuple

Pk = str
Pair = Tuple[str, str]   # нормализовано: a < b


class Mark:
    __slots__ = ("pair", "against", "frm", "until")

    def __init__(self, pair: Pair, against: Pk, frm: float, until: float):
        self.pair, self.against, self.frm, self.until = pair, against, frm, until


class Registry:
    def __init__(self, half_life: float):
        self.T = half_life
        self.instance: Dict[Pair, float] = {}     # пара -> t_c экземпляра
        self.marks: List[Mark] = []

    @staticmethod
    def _norm(u: Pk, v: Pk) -> Pair:
        return (u, v) if u < v else (v, u)

    def link(self, u: Pk, v: Pk, t: float) -> None:
        """LINK(u,v): новый экземпляр; ПЕРЕТИРАЕТ разрывы этой пары."""
        p = self._norm(u, v)
        for m in self.marks:
            if m.pair == p and m.until > t:
                m.until = t
        self.instance[p] = t

    def break_link(self, breaker: Pk, other: Pk, t: float) -> bool:
        """BREAK(u->v): только для живого экземпляра; метка против покинутого."""
        p = self._norm(breaker, other)
        tc = self.instance.get(p)
        if tc is None or tc > t:
            return False                       # рвать нечего
        if t >= self._decay_of(breaker, other, tc):
            return False                       # уже распалась
        del self.instance[p]
        self.marks.append(Mark(p, other, t, tc + self.T))
        return True

    def N(self, pk: Pk, t: float) -> int:
        return sum(1 for m in self.marks
                   if m.against == pk and m.frm <= t < m.until)

    def window(self, u: Pk, v: Pk, t: float) -> float:
        return self.T / (1.0 + self.N(u, t) + self.N(v, t))

    def decay_time(self, u: Pk, v: Pk) -> Optional[float]:
        tc = self.instance.get(self._norm(u, v))
        return None if tc is None else self._decay_of(u, v, tc)

    def active(self, u: Pk, v: Pk, t: float) -> bool:
        tc = self.instance.get(self._norm(u, v))
        return tc is not None and tc <= t and t < self._decay_of(u, v, tc)

    def _decay_of(self, u: Pk, v: Pk, tc: float) -> float:
        pts = {tc, tc + self.T}
        for m in self.marks:
            if m.against not in (u, v):
                continue
            if tc < m.frm <= tc + self.T:
                pts.add(m.frm)
            if tc < m.until <= tc + self.T:
                pts.add(m.until)
        seg = sorted(pts)

            w = self.window(u, v, s1)          # постоянно на [s1, s2)
            cand = max(s1, tc + w)
            if cand < s2:
                return cand
        return tc + self.T                     # W <= T всегда
```

```cpp
using Links = std::set<Link>;

struct Params {
    double c        = 0.25;
    double floorDiv = 2.5;
    int    floorCap = 4500;
    size_t kMin = 2, kMax = 10;
    size_t l0Min = 4, l0Max = 30;
    long   attestationWindow = 2;
    double eps = 1e-9;
};
const Params P;

double fCurve(double m) {
    if (m < 30.0) return 0.5;
    if (m <= 1e4) return 0.05 + 0.45  * std::pow(1.5, -std::log10(m / 30.0));
    return           0.05 + 0.1618 * std::pow(4.0, -std::log10(m / 1e4));
}
int conspiracyFloor(double m) {
    return std::min<int>(int(std::floor(m / P.floorDiv + P.eps)), P.floorCap);
}
double gamma(double rho, double fAvg) {
    return std::min(1.0, fAvg + P.c * (rho - 1.0));
}
int sideThreshold(size_t selfSize, size_t otherSize) {
    const size_t s = std::min(selfSize, otherSize);
    const size_t b = std::max(selfSize, otherSize);
    const double avg = (s + b) / 2.0;
    const double fa  = fCurve(avg);
    const int    fl  = conspiracyFloor(avg);
    const double g   = gamma(double(b) / double(s), fa);

    const int tBig = std::min<int>(int(b),
                       std::max(int(std::floor(fa * b + P.eps)), fl) + 1);
    const int tSmall = std::min<int>(int(s),
                         std::max({int(std::floor(fa * s + P.eps)),
                                   int(std::floor(g  * s + P.eps)), fl}) + 1);
    return (selfSize == b) ? tBig : tSmall;
}

struct Group {
    std::string id;
    int  level = 0;
    std::vector<Pk> roster;
    std::map<Pk, long> attestedAt;
    long frozenUntil = 0;
    bool revalidated = true;
    size_t size() const { return roster.size(); }
};

Link mkLink(const Pk& a, const Pk& b) { return a < b ? Link{a, b} : Link{b, a}; }
void addClique(const Group& g, Links& links) {
    for (size_t i = 0; i < g.roster.size(); ++i)
        for (size_t j = i + 1; j < g.roster.size(); ++j)
            links.insert(mkLink(g.roster[i], g.roster[j]));
}
void addBiclique(const std::vector<Pk>& xs, const std::vector<Pk>& ys, Links& links) {
    for (const auto& x : xs) for (const auto& y : ys) links.insert(mkLink(x, y));
}

bool attestationsFresh(const Group& g, long now) {
    for (const auto& pk : g.roster) {
        auto it = g.attestedAt.find(pk);
        if (it == g.attestedAt.end() || now - it->second > P.attestationWindow)
            return false;
    }
    return true;
}
bool cohesionOk(const Group& g, const Links& links) {
    std::set<Pk> rs(g.roster.begin(), g.roster.end());
    std::map<Pk, int> deg;
    for (const auto& [a, b] : links)
        if (rs.count(a) && rs.count(b)) { ++deg[a]; ++deg[b]; }
    const int need = int(g.size()) / 2 + 1;
    for (const auto& pk : g.roster)
        if (deg[pk] < need) return false;
    return true;
}
std::set<Pk> directedU(const Group& A, const Group& B, const Links& links) {
    std::set<Pk> ra(A.roster.begin(), A.roster.end());
    std::set<Pk> rb(B.roster.begin(), B.roster.end());
    std::set<Pk> u;
    for (const auto& [a, b] : links) {
        if (ra.count(a) && rb.count(b)) u.insert(a);
        if (ra.count(b) && rb.count(a)) u.insert(b);
    }
    return u;
}

struct PairDiag { std::string a, b; int uAb, uBa, tA, tB; bool edge; };

    bool ok = false;
    std::vector<std::string> errors;
    std::vector<PairDiag> pairs;
    size_t newSize = 0;
};

MergeReport verifyMerge(const std::vector<const Group*>& m, const Links& links,
                        long now,
                        const std::vector<std::set<std::string>>& liveParentChildren = {})
{
    MergeReport rep;
    const size_t k = m.size();

    if (k < P.kMin || k > P.kMax)
        rep.errors.push_back("ширина слияния вне [2,10]");

    for (const Group* g : m) {
        if (g->level == 0) {
            if (g->size() < P.l0Min || g->size() > P.l0Max)
                rep.errors.push_back(g->id + ": размер L0 вне [4,30]");
            if (!cohesionOk(*g, links))
                rep.errors.push_back(g->id + ": нарушена когезия L0");
            if (!attestationsFresh(*g, now))
                rep.errors.push_back(g->id + ": просрочена само-аттестация члена");
        } else if (!g->revalidated) {
            rep.errors.push_back(g->id + ": не прошла эпохальную перепроверку");
        }
        if (g->frozenUntil > now)
            rep.errors.push_back(g->id + ": заморожена до эпохи " +
                                 std::to_string(g->frozenUntil));
    }

    std::vector<std::vector<int>> adj(k);
    for (size_t i = 0; i < k; ++i)
        for (size_t j = i + 1; j < k; ++j) {
            const Group& A = *m[i], & B = *m[j];
            const int uAb = int(directedU(A, B, links).size());
            const int uBa = int(directedU(B, A, links).size());
            const int tA  = sideThreshold(A.size(), B.size());
            const int tB  = sideThreshold(B.size(), A.size());
            const bool edge = (uAb >= tA) && (uBa >= tB);
            rep.pairs.push_back({A.id, B.id, uAb, uBa, tA, tB, edge});
            if (edge) { adj[i].push_back(int(j)); adj[j].push_back(int(i)); }
        }

    if (k > 0) {
        std::vector<char> seen(k, 0);
        std::vector<int> stack{0};
        seen[0] = 1;
        size_t reached = 1;
        while (!stack.empty()) {
            const int u = stack.back(); stack.pop_back();
            for (const int v : adj[u])
                if (!seen[v]) { seen[v] = 1; ++reached; stack.push_back(v); }
        }
        if (reached != k) rep.errors.push_back("граф слияния несвязен");
    }

    if (k >= 3) {
        std::vector<int> disc(k, 0), low(k, 0);
        int timer = 0;
        std::vector<std::pair<int,int>> bridges;
        std::function<void(int,int)> dfs = [&](int u, int parent) {
            disc[u] = low[u] = ++timer;
            for (const int v : adj[u]) {
                if (v == parent) continue;
                if (!disc[v]) {
                    dfs(v, u);
                    low[u] = std::min(low[u], low[v]);
                    if (low[v] > disc[u]) bridges.push_back({u, v});
                } else low[u] = std::min(low[u], disc[v]);
            }
        };
        for (size_t r = 0; r < k; ++r)
            if (!disc[r]) dfs(int(r), -1);
        if (!bridges.empty())
            rep.errors.push_back("граф слияния содержит мосты (k >= 3)");
    }

    std::set<Pk> un;
    size_t maxChild = 0;
    for (const Group* g : m) {
        un.insert(g->roster.begin(), g->roster.end());
        maxChild = std::max(maxChild, g->size());
    }
    rep.newSize = un.size();
    if (!m.empty() && rep.newSize <= maxChild)
        rep.errors.push_back("правило роста нарушено: |G_new| <= max|G_i|");

    std::set<std::string> mids;
    for (const Group* g : m) mids.insert(g->id);
    for (const auto& kids : liveParentChildren)
        if (kids == mids) {
            rep.errors.push_back("M совпадает с множеством детей живого родителя");
            break;
        }

    rep.ok = rep.errors.empty();
    return rep;
}

Group makeL0(const std::string& id, const std::string& prefix, size_t n, long now) {
    Group g; g.id = id;
    for (size_t i = 0; i < n; ++i) {
        const Pk pk = prefix + std::to_string(i + 1);
        g.roster.push_back(pk);
        g.attestedAt[pk] = now;
    }
    return g;
}

        for (const auto& e : r.errors) std::cout << "    - " << e << "\n";
        std::cout << "\n";
    }
}
```

```python
#!/usr/bin/env python3
# =====================================================================
# PoSoc — эталонная верификация слияния групп.
# =====================================================================
from __future__ import annotations

from dataclasses import dataclass, field
from math import floor, log10
from typing import Dict, List, Set, Tuple

EPS = 1e-9
C = 0.25
FLOOR_DIV, FLOOR_CAP = 2.5, 4500
K_MIN, K_MAX = 2, 10
L0_MIN, L0_MAX = 4, 30
ATT_WINDOW = 2


def f_curve(m: float) -> float:
    if m < 30:
        return 0.5
    if m <= 1e4:
        return 0.05 + 0.45 * 1.5 ** (-log10(m / 30))
    return 0.05 + 0.1618 * 4.0 ** (-log10(m / 1e4))


def conspiracy_floor(m: float) -> int:
    return min(floor(m / FLOOR_DIV + EPS), FLOOR_CAP)


def gamma(rho: float, f_avg: float) -> float:
    return min(1.0, f_avg + C * (rho - 1.0))


def side_threshold(self_size: int, other_size: int) -> int:
    s, b = min(self_size, other_size), max(self_size, other_size)
    avg = (s + b) / 2
    fa = f_curve(avg)
    fl = conspiracy_floor(avg)
    g = gamma(b / s, fa)
    t_big = min(b, max(floor(fa * b + EPS), fl) + 1)
    t_small = min(s, max(floor(fa * s + EPS), floor(g * s + EPS), fl) + 1)
    return t_big if self_size == b else t_small


@dataclass
class Group:
    id: str
    level: int = 0
    roster: List[str] = field(default_factory=list)
    attested_at: Dict[str, int] = field(default_factory=dict)
    frozen_until: int = 0
    revalidated: bool = True

    @property
    def size(self) -> int:
        return len(self.roster)


Link = Tuple[str, str]


def norm_link(a: str, b: str) -> Link:
    return (a, b) if a < b else (b, a)


def add_clique(g: Group, links: Set[Link]) -> None:
    r = g.roster
    for i in range(len(r)):
        for j in range(i + 1, len(r)):
            links.add(norm_link(r[i], r[j]))


def add_biclique(xs, ys, links: Set[Link]) -> None:
    for x in xs:
        for y in ys:
            links.add(norm_link(x, y))


def attestations_fresh(g: Group, now: int) -> bool:
    return all(now - g.attested_at.get(pk, -(10 ** 9)) <= ATT_WINDOW
               for pk in g.roster)


def cohesion_ok(g: Group, links: Set[Link]) -> bool:
    rs = set(g.roster)
    deg = {pk: 0 for pk in g.roster}
    for a, b in links:
        if a in rs and b in rs:
            deg[a] += 1
            deg[b] += 1
    need = len(g.roster) // 2 + 1
    return all(deg[pk] >= need for pk in g.roster)


def directed_u(a: Group, b: Group, links: Set[Link]) -> Set[str]:
    ra, rb = set(a.roster), set(b.roster)
    u: Set[str] = set()
    for x, y in links:
        if x in ra and y in rb:
            u.add(x)
        if y in ra and x in rb:
            u.add(y)
    return u


@dataclass
class PairDiag:
    a: str
    b: str
    u_ab: int
    u_ba: int
    t_a: int
    t_b: int
    edge: bool


@dataclass
class MergeReport:
    ok: bool = False
    errors: List[str] = field(default_factory=list)
    pairs: List[PairDiag] = field(default_factory=list)
    new_size: int = 0


def verify_merge(groups: List[Group], links: Set[Link], now: int,
                 live_parent_children: List[Set[str]] = ()) -> MergeReport:
    rep = MergeReport()
    k = len(groups)

    if not (K_MIN <= k <= K_MAX):
        rep.errors.append(f"ширина слияния {k} вне [{K_MIN},{K_MAX}]")

    for g in groups:
        if g.level == 0:
            if not (L0_MIN <= g.size <= L0_MAX):
                rep.errors.append(f"{g.id}: размер L0 вне [{L0_MIN},{L0_MAX}]")
            if not cohesion_ok(g, links):
                rep.errors.append(f"{g.id}: нарушена когезия L0")
            if not attestations_fresh(g, now):
                rep.errors.append(f"{g.id}: просрочена само-аттестация члена")
        elif not g.revalidated:
            rep.errors.append(f"{g.id}: не прошла эпохальную перепроверку")
        if g.frozen_until > now:
            rep.errors.append(f"{g.id}: заморожена до эпохи {g.frozen_until}")

    adj: List[List[int]] = [[] for _ in range(k)]
    for i in range(k):
        for j in range(i + 1, k):
            a, b = groups[i], groups[j]
            u_ab = len(directed_u(a, b, links))
            u_ba = len(directed_u(b, a, links))
            t_a = side_threshold(a.size, b.size)
            t_b = side_threshold(b.size, a.size)
            edge = u_ab >= t_a and u_ba >= t_b
            rep.pairs.append(PairDiag(a.id, b.id, u_ab, u_ba, t_a, t_b, edge))
            if edge:
                adj[i].append(j)
                adj[j].append(i)

    if k:
        seen, stack = {0}, [0]
        while stack:
            u = stack.pop()
            for v in adj[u]:
                if v not in seen:
                    seen.add(v)
                    stack.append(v)
        if len(seen) != k:
            rep.errors.append("граф слияния несвязен")

    if k >= 3:
        disc, low = [0] * k, [0] * k
        timer = 0
        bridges: List[Tuple[int, int]] = []

        def dfs(u: int, parent: int) -> None:
            nonlocal timer
            timer += 1
            disc[u] = low[u] = timer
            for v in adj[u]:
                if v == parent:
                    continue
                if not disc[v]:
                    dfs(v, u)
                    low[u] = min(low[u], low[v])
                    if low[v] > disc[u]:
                        bridges.append((u, v))
                else:
                    low[u] = min(low[u], disc[v])

        for r in range(k):
            if not disc[r]:
                dfs(r, -1)
        if bridges:
            rep.errors.append(f"граф слияния содержит мосты (k >= 3): {bridges}")

    union: Set[str] = set()
    max_child = 0
    for g in groups:
        union.update(g.roster)
        max_child = max(max_child, g.size)
    rep.new_size = len(union)
    if groups and rep.new_size <= max_child:
        rep.errors.append("правило роста нарушено: |G_new| <= max|G_i|")

    mids = {g.id for g in groups}
    if any(kids == mids for kids in live_parent_children):
        rep.errors.append("M совпадает с множеством детей живого родителя")

    rep.ok = not rep.errors
    return rep
```
